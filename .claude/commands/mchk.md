PR 본문 「## 팀원에게」의 메시지를 **읽기 전용**으로 모아 상태별로 나눠 보여 준다. 파일·PR·브랜치를 바꾸지 않고, 시작도 하지 않는다(CLAUDE.md: 시작은 사람이 정한다).

## 1. 모으기
- '나'는 `git config vcc.me`(없으면 user.name·email로 짐작: 미리·민지·원우).
- `gh pr list -R hufsiei/VCC --state all --limit 100 --json number,title,state,isDraft,mergedAt,updatedAt,headRefName,body` 로 열린 PR 전부 + 7일 안 병합·닫힌 PR을 읽는다.
- 본문의 「## 팀원에게」 절에서 `[to…]` 묶음 중 나에게 온 것(`[to나]`·`[to전원]`·`[to원우·나]` 포함)을 항목(1. 2. …)별로 쪼갠다. 본 것·안 본 것 가리지 않고 전부 본다(11/25부터 세션 시작 hook은 메시지를 띄우지 않는다 — 팀원 메시지는 여기서만 본다).

## 2. 항목마다 상태 판정
각 항목(요청·결정요망·통지·참고)을 아래 셋 중 하나로 나눈다. 판정 근거는 실제로 확인한다 — 추측으로 「해결」이라 쓰지 않는다.

- **해결됨**: 그 PR이 merged이고 항목 내용이 main에 들어와 있거나, 요청한 일이 이미 main/후속 PR에서 끝난 것이 확인됨(`git log origin/main`, `git grep`, 해당 PR·파일 확인). 통지·참고는 PR이 merged/closed면 해결(읽기만 하면 되는 것)로 본다.
- **작업 중**: 요청한 일을 누군가 지금 하고 있는 흔적이 있음 — `git worktree list`의 VCC-* 폴더와 브랜치(다른 Claude 세션 포함), 열린/draft PR, 원격 브랜치(`git branch -r`), 해당 파일을 고친 브랜치. 어느 폴더·브랜치·PR인지와 누가 하는지 같이 적는다. 다른 PC의 팀원 세션은 원격 브랜치·PR로만 보이므로 그렇게 말한다.
- **해야 함**: 해결도 작업 중도 아닌 것 — (요청)·(결정요망)이 남았거나, 내가 답해야 하는 것. 기한(~MM.DD)이 있으면 같이 적고 급한 순으로 위에 둔다.

흔적이 불확실하면 「확인 못 함」으로 표시하고 이유를 한 줄 쓴다.

## 3. 출력
맨 위에 한 줄 요약: `해야 함 n · 작업 중 n · 해결됨 n`.
그 아래 세 절을 이 순서로(해야 함 → 작업 중 → 해결됨), 항목마다 한 줄:
`PR #번호 (상태) 말머리 — 내용 요약 [근거: 브랜치/PR/커밋]`
비어 있는 절은 「없음」. 해결됨 절은 짧게(번호와 한 줄만).
끝에 해야 함 중 **무엇부터 할지** 한 줄 제안만 한다. 하라고 하기 전에는 시작하지 않는다.
