# milend — 업무 마무리

각자 PC에서 같은 모양으로 쓰는 마무리 루틴이다. **「나」** = `git config vcc.me`(원우|민지|미리), 없으면 `user.name`·`user.email`로 짐작(`.claude/skills/milwork/board.py`의 `who_am_i()`와 같은 방식), 모르면 한 번 묻는다. 「**미리만**」 표시가 붙은 절(작업내역서·작업일지)은 `vcc.me`가 미리일 때만 하고, 아니면 건너뛴다. 상태판·큐·결정은 사람별 파일(`board-<이름>.md`)이고 `board.py`가 자동으로 내 파일을 쓴다. 담당 검사는 CLAUDE.md 「누가 무엇을 고치나」를 나 기준으로 본다.

**미리만:** 작업내역서 갱신안은 내가 「좋아」 한 뒤에 쓴다. 작업일지는 승인 없이 바로 저장한다.

## 1. 세션 정리
- 상태판: `python -X utf8 C:/dev/VCC/.claude/skills/milwork/board.py list`(아래 `board.py`). 줄마다 브랜치가 병합됐는지 `gh pr list --state merged --head <브랜치>`로 본다. 병합된 것은 폴더를 지우고(`cd /c/dev` 후 `git worktree remove`, 실패하면 `rm -rf`) `board.py remove <폴더>`. 병합 안 된 것은 상태를 알리고 나에게 묻는다(내일 다른 PC에서 이어 한다면 브랜치를 push해 두라고 권한다). 상태판에 없는 `C:\dev\VCC-*` 폴더도 같은 기준으로 정리한다. 상태판은 드라이브 `@VCC\총괄\board-<이름>.md`(사람별, 두 PC 공용)다.
- 큐: `board.py queue`에서 「제안」·「승인」으로 남은 줄(내일로 넘길 것)과 `board.py decide`의 답 없는 결정요망을 보고에 넣는다. 병합된 작업의 큐 줄은 `board.py queue done Q-n --pr <번호>`로 「완료」로 닫는다(「반려」는 안 하기로 한 일에만). 줄을 손으로 지우지 않는다(지난 줄은 아래 `clean`이 지운다). 폴더를 `remove`하면 그 폴더 큐 줄(시작됨)은 자동으로 완료가 되지만 PR 번호는 `queue done`으로 남긴다.
- 위의 완료 처리와 답 확인을 마친 뒤 `board.py clean --days 1`: 완료·반려가 된 지 하루 넘은 큐 줄과, 답한 지 하루 넘은 결정요망을 지운다. 번호는 상태판 머리 「마지막 번호」에서 이어진다.
- 끝으로 `board.py chief --set –`로 총괄 세션 이름을 비운다(내일 milstart가 다시 적는다). 켜 둔 `/loop … /milwatch`는 이 창을 닫으면 같이 꺼진다고 알린다.
- 오늘 연 내 PR 중 병합 안 된 것, 리뷰를 기다리는 팀원 PR 목록.
- 켜 둔 서버: `netstat -ano | grep -E ":8787|:8000"`. 있으면 끌지 묻는다(local_fn.py, serve_screens.py).
- `C:\dev\VCC`가 main이고 깨끗한지. 아니면 이유와 「직접 pull하세요: `git -C C:/dev/VCC pull`」 한 줄을 알린다(대신 되돌리지 않는다).

## 2. 작업내역서 대조·갱신 — 미리만
- 오늘 병합된 PR: `gh pr list -R hufsiei/VCC --state merged --search "merged:>=<오늘 YYYY-MM-DD>" --limit 50 --json number,title,mergedAt,author`. PR 제목·본문의 「작업 N」으로 작업 번호를 찾는다.
- `H:\내 드라이브\@VCC\@VCC작업내역 v6.xlsx` `작업목록` 시트와 대조해 **갱신안 표**를 먼저 보여 준다: 번호 · 칸(진행상황/비고/막힌 점) · 지금 값 → 새 값. 비고는 기존 형식대로 끝에 `[MM/DD 밤] (미리) …` 한두 줄을 덧붙인다(지우지 않는다). 참고할 점(다음 사람이 알아야 할 것)도 짧게 메모로.
- 승인 뒤 쓰기:
  1. 엑셀에서 파일이 열려 있으면 저장이 안 된다 — 닫아 달라고 한다.
  2. 백업: `H:\내 드라이브\@VCC\이전 파일\@VCC작업내역 v6_백업_MMDD_HHMM.xlsx`로 복사.
  3. openpyxl로 **해당 칸만** 바꿔 저장(차트·그림 없음). 저장 후 다시 읽어 바뀐 칸 수가 갱신안과 같은지 확인.
  4. 드라이브 동기화가 끝나야 다른 PC에서 새 파일이 보인다고 알린다.

## 3. 작업일지 — 미리만
(원우·민지는 각자 평소대로 일지를 쓴다. 이 절은 건너뛴다.)
- 파일: `H:\내 드라이브\@VCC\작업일지\외대인사이드_작업일지_MMDD_미리.md`. **직전 일지를 읽지 않고** 아래 고정 틀로 쓴다. 재료는 오늘 병합·올린 PR, 2절 갱신안, 오늘 대화.

```
# 외대인사이드 작업일지 MM/DD (미리)

## 오늘 3줄
- …
- …
- …

## 작업별
### 작업 N <제목> — PR #n (merged|open)
- 한 일:
- 결과·수치:
- 남은 것:

## 잘 된 프롬프트
(원문 그대로 1~2개. 없으면 「없음」)

## 내일
- …
```
- 승인 없이 바로 드라이브에 저장하고, 저장한 경로와 「오늘 3줄」만 알린다. 같은 날 낮판이 있으면 덮지 말고 「밤판」으로 갱신한다(낮판 내용 유지 + 추가).

## 4. 내게 넘길 것 (마지막 메시지)
- **내일 리마인드**: 내일 어느 PC인지 묻지 말고 내가 말한 대로. 3~5줄 —
  - 오늘 끝내지 못한 일과 다음 한 걸음
  - 팀원 답을 기다리는 것(누구에게 무엇 — PR 본문 「팀원에게」로 보낸 것)
  - 내가 결정할 것
  - PC를 바꾸는 날이면: `.env`를 오늘 바꿨는지(바꿨으면 Bitwarden 갱신은 내가), 드라이브 동기화 완료 확인

## 작업 규칙
milstart의 「작업 규칙」과 같다(worktree에서만 수정, .env 비공개, heredoc 대신 Write, 폴더 삭제 시 `cd /c/dev`, 담당 폴더 존중, 팀원 메시지는 써 주되 보내기는 내가).
