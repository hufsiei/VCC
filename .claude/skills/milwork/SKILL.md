# milwork — 작업 하나 시작 (작업 대화창용)

미리는 VS Code 창 하나에 Claude 대화창을 여러 개 띄워 일한다. 이 루틴을 친 대화창은 **작업 대화창**이 된다: 작업 폴더 하나를 만들어 거기서만 고치고, 진행 상태를 상태판에 남긴다. 총괄 일(PR 검토·병합·팀원 전달·작업내역서)은 하지 않는다 — 그건 총괄 대화창의 milstart·milreview·milend 몫이다. VS Code 창을 새로 열 필요는 없다.

상태판 도구: `python -X utf8 C:/dev/VCC/.claude/skills/milwork/board.py <명령>` (아래에서 `board.py`로 줄여 씀). 상태판 파일은 `C:\dev\VCC-board.md`, 이 PC의 것이다.

## 1. 입력 해석
- 형식: `milwork <요청자> <작업 제목>`. 요청자는 원우 · 민지 · 미리(혼자 할 일) · 상의(상위 모델과 상의한 결론을 반영하는 일) 중 하나. 작업내역서 번호(「작업 N」)가 있으면 함께 받는다.
- 요청자나 제목이 없으면 한 번만 묻고, 둘 다 있으면 바로 진행한다.
- 영문 이름: 원우 `wonwoo` · 민지 `minji` · 미리 `miri` · 상의 `talk`. 제목에서 영문 소문자 2~3단어를 뽑아 하이픈으로 잇는다(예: `score-weight`). 브랜치 `<영문이름>/<슬러그>`, 폴더 `C:\dev\VCC-<슬러그>`. 폴더가 이미 있으면 `-2`를 붙인다.

## 2. 상태판 먼저 보기
```
board.py list
```
- 같은 작업(제목·브랜치가 같은 줄)이 이미 있으면 새로 만들지 않는다. "그 폴더에서 이어서 할까요?"라고 묻고, 이어 하면 그 폴더를 이 대화창의 작업 폴더로 삼는다(3단계 건너뜀).
- 「폴더 없음」 줄이나 「상태판에 없음」 worktree가 보이면 한 줄로 알리기만 한다. 정리는 총괄 대화창(milend)이 한다.

## 3. 담당·충돌 확인 → 폴더 만들기
- 제목으로 **고칠 파일을 예상**하고 CLAUDE.md 「누가 무엇을 고치나」와 맞춰 본다. 요청자 몫이 아닌 파일(예: 원우 요청인데 `screens/`)이면 알리고 계속할지 묻는다 — 미리가 정한다.
- 예상 파일로 `board.py check <파일...>`. 종료코드 2(겹침)면 **폴더를 만들지 않고 멈춰** 어느 대화창과 겹치는지 보여 준다. 같은 날 같은 파일을 두 곳에서 고치지 않는다.
- 만들기:
```
git -C C:/dev/VCC fetch -q origin
git -C C:/dev/VCC worktree add -b <브랜치> C:/dev/VCC-<슬러그> origin/main
board.py add VCC-<슬러그> --branch <브랜치> --who <요청자> --task "<제목>" --files <예상 파일,…>
```
`C:\dev\VCC`가 main이고 깨끗하면 `git -C C:/dev/VCC pull --ff-only -q`도 해 둔다(아니면 건너뛰고 이유만 알린다).

## 4. 보고 (3~4줄)
폴더·브랜치, 예상 파일과 담당 확인 결과, 겹침 여부, 그리고 **"이 대화창은 이제 `C:\dev\VCC-<슬러그>`만 고칩니다."** 끝에 바로 작업을 시작한다(미리가 막지 않으면). 고친 파일을 편집기에서 보고 싶으면 「파일 > 작업 영역에 폴더 추가」로 그 폴더를 붙일 수 있다고 한 번만 알린다.

## 작업 중 규칙
- 모든 읽기·쓰기는 절대 경로 `C:/dev/VCC-<슬러그>/...`로 한다. `C:\dev\VCC`는 비교·참고용으로 읽기만 하고 고치지 않는다. `.env`·로그는 `functions/paths.py`가 본 저장소 것을 쓰므로 복사하지 않는다. `.env`는 읽어서 보여 주지 않는다.
- **파일을 처음 고치기 전** `board.py check <파일> --me VCC-<슬러그>`. 겹치면 멈추고 알린다. 고친 파일은 커밋할 때 `board.py set VCC-<슬러그> --files <파일,…>`로 적는다.
- 상태는 바뀔 때마다 `board.py set VCC-<슬러그> --status "<상태>"`: `시작` → `고치는 중` → `시험 통과` → `PR #n 올림`. 막혔으면 `막힘: <한 줄>`.
- 시험은 기존 규칙대로(`functions/test_*.py`, `tools/*.py --help`, 화면은 390px). AI를 실제로 부르는 시험은 호출 수·예상 금액을 먼저 말하고 승인받는다.
- 커밋·PR 제목은 `[미리] <무엇> (작업 N)`. PR 본문에 「확인 전」 항목을 남긴다. 병합은 하지 않는다 — 총괄 대화창에서 milreview 뒤 미리가 한다.
- 팀원에게 보낼 글은 쓰지도 보내지도 않는다. 대신 PR을 올린 뒤:
```
board.py set VCC-<슬러그> --status "PR #n 올림" --handoff "원우에게: PR #n 확인 요청 · 바뀐 점 한 줄"
```
- 요청자가 「상의」면 상의 대화창의 결론을 그대로 받아 반영한다. 결론과 다르게 고쳐야 할 이유가 보이면 고치기 전에 말한다.
- 폴더와 상태판 줄은 지우지 않는다. PR이 병합되면 총괄 대화창의 milend가 지운다.
- 작업이 끝나면 "총괄 대화창에서 밀리뷰(검토)·밀종료(전달·정리)를 돌리세요"라고 한 줄 남긴다. 이 대화창에서 **다른 작업을 이어 하려면 `milwork …`를 다시 친다**(폴더 안에서 브랜치를 갈아타지 않는다).

## 공통 규칙
파일 패치 스크립트는 Bash heredoc 대신 Write 도구로 만들어 실행한다. 폴더 삭제는 하지 않는다. `data/`·`tools/`·`functions/score.py`는 원우, `screens/`·`common/style.css`·`docs/design-rules.md`는 민지 담당 — 요청자가 그 사람이어도 미리 이름으로 고치는 것이니 PR 본문에 「○○ 요청으로 미리가 고침」을 적는다.
