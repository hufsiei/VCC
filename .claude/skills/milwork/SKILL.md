# milwork — 작업 하나 시작 (작업 대화창용)

**「나」= 이 PC의 사람.** `git config vcc.me`(원우|민지|미리)로 정하고, 없으면 `git config user.name`·`user.email`에 든 글자로 짐작한다(`.claude/skills/milwork/board.py`의 `who_am_i()`와 같은 방식). 모르면 한 번만 묻는다. 이 글의 「나」·「내」는 모두 이 사람이다.

나는 VS Code 창 하나에 Claude 대화창을 여러 개 띄워 일한다. 이 루틴을 친 대화창은 **작업 대화창**이 된다: 작업 폴더 하나를 만들어 거기서만 고치고, 진행 상태를 내 상태판에 남긴다. 총괄 일(PR 병합·작업내역서·작업일지·하루 정리)은 하지 않는다 — **vcc.me가 미리일 때만** 총괄 대화창의 milstart·milreview·milend로 한다. **다른 사람에게 보내는 요청·알림은 PR 본문 「## 팀원에게」에 완성본으로 쓴다**(받는 사람이 `/mchk`로 읽는다. 단톡용 글은 따로 쓰지 않는다). 검토 뒤 더할 말은 미리의 총괄 대화창(milreview)이 같은 절에 더한다. 단 다른 사람이 보낸 질문에 대한 답장은 받은 대화창이 바로 쓴다(아래 「다른 사람 메시지가 오면」). VS Code 창을 새로 열 필요는 없다.

상태판 도구: `python -X utf8 C:/dev/VCC/.claude/skills/milwork/board.py <명령>` (아래에서 `board.py`로 줄여 씀). 상태판·큐·결정은 **사람별 파일 `board-<이름>.md`**이고 명령은 자동으로 내 파일을 쓴다(파일 위치는 board.py가 정한다).

## 1. 입력 해석
- 형식: `milwork <요청자> <슬러그> <작업 제목>`(슬러그는 생략 가능). 요청자는 원우 · 민지 · 미리 · 상의(상위 모델과 상의한 결론을 반영하는 일) 중 하나이고, 내가 혼자 정한 일이면 요청자는 나다. 작업내역서 번호(「작업 N」)가 있으면 함께 받는다.
- 요청자나 제목이 없으면 한 번만 묻고, 둘 다 있으면 바로 진행한다.
- 영문 이름: 원우 `wonwoo` · 민지 `minji` · 미리 `miri` · 상의 `talk`.
- **슬러그 = 대화창 이름 = 폴더 이름**(11/25, 헷갈림 방지). 요청자 다음 낱말이 영문 소문자·하이픈(예: `cloud-harden`)이면 그대로 슬러그로 쓴다 — 대화창 제목이 첫 줄에서 나오므로 창 이름과 폴더가 같아진다. 없으면 제목에서 영문 소문자 2~3단어를 뽑아 하이픈으로 잇고(예: `score-weight`), 4단계 보고 첫 줄에 「이 창 이름: `<슬러그>`」를 적는다. 상태판 `--task`는 `"<슬러그> <제목>"`으로 적어 상태판·보고·PR 어디서나 같은 이름으로 찾게 한다. 브랜치 `<내 영문이름>/<슬러그>`, 폴더 `C:\dev\VCC-<슬러그>`. 폴더가 이미 있으면 `-2`를 붙인다.

## 1-1. 큐 관문
작업창은 **큐에 있는 일만** 시작한다. 내 세션 이름은 ListAgents 결과 첫 줄 「This session is <이름>」에서 읽는다.
- 지시문에 `Q-n`이 있으면: `board.py queue take Q-n --folder VCC-<슬러그> --session <내 세션이름>`
- `Q-n`이 없으면 내가 직접 붙인 지시문이다(내 지시는 승인된 것으로 친다): `board.py queue add --task "<작업번호 또는 –> <제목>" --files a,b --from 직접` →「Q-n 승인」(자동 승인) 출력 뒤 바로 `queue take`. 누가 쳐도 같은 값이다.
- `take`가 종료코드 2(제안·반려 상태 — 승인 안 됨)면 **폴더를 만들지 않고** 이유를 보여 준 뒤 멈춘다. 겹침은 `queue approve`에서 거르니 여기서는 3단계 `check`가 한 번 더 본다.

## 2. 상태판 먼저 보기
```
board.py list
```
- 출력에 큐·결정요망이 함께 나온다. 내 일과 겹치는 항목이 있는지 같이 본다.
- 같은 작업(제목·브랜치가 같은 줄)이 이미 있으면 새로 만들지 않는다. "그 폴더에서 이어서 할까요?"라고 묻고, 이어 하면 그 폴더를 이 대화창의 작업 폴더로 삼는다(3단계 건너뜀).
- 「폴더 없음」 줄이나 「상태판에 없음」 worktree가 보이면 한 줄로 알리기만 한다. 정리는 하루 마무리(milend)가 한다.

## 3. 담당·충돌 확인 → 폴더 만들기
- 제목으로 **고칠 파일을 예상**하고 CLAUDE.md 「누가 무엇을 고치나」를 **나 기준**으로 맞춰 본다. 내 몫이 아닌 파일(예: 내가 원우인데 `screens/`)이면 알리고 멈춘다. 그 파일의 담당자에게 요청하는 글은 PR 본문 「## 팀원에게」로 쓴다. 내가 미리면 계속할지 내가 정한다(아래 「공통 규칙」 참고).
- 예상 파일로 `board.py check <파일...>`. 종료코드 2(겹침)면 **폴더를 만들지 않고 멈춰** 어느 대화창과 겹치는지 보여 준다. 같은 날 같은 파일을 두 곳에서 고치지 않는다.
- 만들기:
```
git -C C:/dev/VCC fetch -q origin
git -C C:/dev/VCC worktree add -b <브랜치> C:/dev/VCC-<슬러그> origin/main
board.py add VCC-<슬러그> --branch <브랜치> --who <요청자> --task "<슬러그> <제목>" --title "<창 제목>" --session <내 세션이름> --files <예상 파일,…>
```
`--title`(창 제목, 11/26): 지시문 첫 줄에서 요청자·슬러그 뒤 글을 `Q-n`만 빼고 그대로 쓴다(예: `milwork 미리 board-tabs 상태판 HTML 개선 Q-57` → `--title "상태판 HTML 개선"`). VS Code 탭이 「milwork <첫 줄 앞부분>」으로 보이니 상태판 HTML 카드 맨 위 큰 글과 탭 글이 같아져 어느 탭을 닫을지 찾기 쉽다. 이어 하는 창에 없으면 `board.py set <폴더> --title "…"`.
`--session`(11/26 Q-61, **꼭 적는다**): ListAgents 첫 줄 「This session is <이름>」의 이름(예: `vcc-ee`). 총괄이 그 창을 찾고(SendMessage), 상태판 HTML이 끝난 창을 **이 PC에서 그 세션이 아직 열려 있을 때만** 「닫아도 돼요」에 보이는 데 쓴다(닫혔거나 다른 PC 창은 접힌 「지난 창」으로). 빠뜨렸으면 `board.py set <폴더> --session <이름>`.
`C:\dev\VCC`가 main이고 깨끗하면 `git -C C:/dev/VCC pull --ff-only -q`도 해 둔다(아니면 건너뛰고 이유만 알린다).

## 4. 보고 (3~4줄)
첫 줄 「이 창 이름: `<슬러그>` · Q-n」. 폴더·브랜치, 예상 파일과 담당 확인 결과, 겹침 여부, 그리고 **"이 대화창은 이제 `C:\dev\VCC-<슬러그>`만 고칩니다."** 끝에 바로 작업을 시작한다(내가 막지 않으면). 고친 파일을 편집기에서 보고 싶으면 「파일 > 작업 영역에 폴더 추가」로 그 폴더를 붙일 수 있다고 한 번만 알린다.

## 작업 중 규칙
- 모든 읽기·쓰기는 절대 경로 `C:/dev/VCC-<슬러그>/...`로 한다. `C:\dev\VCC`는 비교·참고용으로 읽기만 하고 고치지 않는다. `.env`·로그는 `functions/paths.py`가 본 저장소 것을 쓰므로 복사하지 않는다. `.env`는 읽어서 보여 주지 않는다.
- **파일을 처음 고치기 전** `board.py check <파일> --me VCC-<슬러그>`. 겹치면 멈추고 알린다. 고친 파일은 커밋할 때 `board.py set VCC-<슬러그> --files <파일,…>`로 적는다.
- 상태는 바뀔 때마다 `board.py set VCC-<슬러그> --status "<상태>"`: `시작` → `고치는 중` → `시험 통과` → `PR #n 올림`. 막혔으면 `막힘: <한 줄>`.
- 시험은 기존 규칙대로(`functions/test_*.py`, `tools/*.py --help`, 화면은 390px). AI를 실제로 부르는 시험은 호출 수·예상 금액을 먼저 말한다. **하루 기준 $20**(11/23 미리 결정): 오늘 누적(필요하면 `/token`, Sonnet 5.5 $2/$10·Opus 5.5 $4/$20 per 1M) + 예상 금액이 $20 이하면 알리고 진행, 넘으면 승인받는다. HCX는 대회 크레딧(50만 원, ~12/31)에서 빠진다 — 단가 확인 전이라 $에 넣지 못하니 HCX 호출 수·토큰을 함께 보고한다.
- **캡처·산출물은 작업 폴더(`C:/dev/VCC-<슬러그>/`)에 저장한다. 본 폴더 `C:\dev\VCC`에 쓰지 않는다**(11/25: 본 폴더 미추적 캡처가 pull을 막아 170커밋 밀림).
- 커밋·PR 제목은 `[<내 이름>] <무엇> (작업 N)`. PR 본문에 「확인 전」 항목을 남긴다. 병합은 하지 않는다 — **PR 병합 확인 책임자는 미리**다(vcc.me가 미리면 총괄 대화창에서 milreview 뒤 내가 한다).
- 다른 사람 커밋·작업을 대신 올리기 전에 그 사람이 이미 연 PR이 있는지 본다: `gh pr list --state open --author <GitHub 아이디>`(브랜치 이름으로도 `--head <브랜치>`). 있으면 새로 올리지 않고 그 PR을 검토한다(11/23 #171이 민지 #170과 중복된 일).
- PR 본문 끝(🤖 줄 위)에 「## 팀원에게」 절을 쓴다: CLAUDE.md 「팀원에게 보내는 메시지」 형식 그대로, 받는 사람별 `[to이름] PR #n open — …` 묶음. `/mchk`가 이 머리 줄로 받는 사람을 가리므로 「민지에게: …」 같은 다른 모양으로 쓰지 않는다. 알릴 사람이 없으면 「없음」(이때 아래 번호 순서는 건너뛴다).
  - **PR 번호는 만든 뒤에야 안다** — 순서: ① 본문 머리 줄을 `[to민지] PR #? open — <제목>`처럼 자리만 두고 쓴다. ② `gh pr create`로 PR을 만들어 번호 n을 받는다. ③ 본문의 `PR #?`를 n으로 바꿔 `gh pr edit <n> --body-file …`로 다시 올린다. ④ `gh pr view <n> --json body`에서 `[to` 줄마다 `PR #<n> open`(draft면 `draft`)이 있는지 확인하고, 없으면 고쳐 다시 올린다. 예: `[to민지] PR #270 open — 동의 시트 Q 인용`.
  - 총괄에 보내는 `[PR #n]` 알림(아래 (d))은 ④ 확인 뒤에 보낸다.
  - 상태판은 `board.py set VCC-<슬러그> --status "PR #n 올림"`만(`--handoff`는 쓰지 않는다).

## 총괄 세션에 알리기
총괄 세션 이름은 `board.py chief`로 읽는다(없으면 빈 줄 + 종료코드 1). 없으면 메시지는 보내지 않고 상태판에만 적고, 보고에 「총괄 세션 없음」 한 줄을 남긴다. 세션 간 전달은 **한 PC 안에서만**이다 — PC·사람 사이는 상태판·PR 본문으로 한다. SendMessage 한 건 한 줄, 머리의 `[ ]`로 종류를 가린다. 보내는 때는 네 가지뿐이다. **작업창은 다른 작업창에 직접 메시지를 보내지 않는다.**
- (a) **파생업무 발견**: `board.py queue add --task "– <제목>" --files a,b --from 파생 --session <내 이름>` →「Q-n 제안」 출력 뒤 `[제안 Q-n] <제목> — <예상 파일>`. 파생업무는 직접 시작하지 않는다(총괄이 `[승인 Q-n]` 또는 `[보류 Q-n] <이유>`로 답하고, 시작은 내가 새 창에서 한다).
- (b) **내가 정할 것**: `board.py decide add --folder VCC-<슬러그> --session <내 이름> --q "질문" --options "A(추천) …; B …"` →「D-n」 출력 뒤 `[결정요망 D-n] <질문> — <선택지>`. 결정에 안 걸리는 부분은 계속 진행하고, 전부 걸리면 멈추고 기다린다. 답은 총괄이 `[결정 D-n] <답>`으로 보내 주니, 받으면 그대로 반영한다. 다른 사람이 정할 것은 여기가 아니라 PR 본문 「## 팀원에게」의 (결정요망)으로 보낸다.
- (c) **막힘**: `board.py set VCC-<슬러그> --status "막힘: …"` 뒤 `[막힘] <슬러그> — <한 줄>`.
- (d) **PR 올림**: `board.py set … --status "PR #n 올림"` 뒤 `[PR #n] <슬러그> — <한 줄>`.

## 다른 사람 메시지가 오면
내가 팀원(나 말고 원우·민지·미리) 메시지를 붙여 넣으면 이 대화창 작업과 상관없는 내용이어도 여기서 처리한다.
1. **pull하고 검토**: `git -C C:/dev/VCC pull --ff-only -q`, 메시지가 말하는 PR·커밋·파일·spec·서버 코드를 실제로 확인한다. 상대가 묻는 값이 서버·spec에 정해져 있지 않으면 "없다"고 말한다(추측해 답하지 않는다). 화면 문구·폭 같은 주장은 가능하면 재 본다(예: 360px).
2. **나에게 보고**: 맞는 것 · 틀린 것 · **내가 정할 것**(선택지와 추천 하나)을 짧게. 정할 것이 없으면 바로 3으로.
3. **답장 쓰기**: 내가 정하면(또는 정할 것이 없으면) 따로 부탁받지 않아도 그 결정을 넣어 바로 답장을 쓴다. 맨 위에 「Written for: ○○」 한 줄, 그다음 코드 블록에 붙여 넣을 글. 글은 **CLAUDE.md 「팀원에게 보내는 메시지」 형식**(머리 줄 + (요청)·(결정요망)·(통지)·(참고) 개조식, 인사·감사 없음)을 따른다. 답이 「PR을 올렸다」는 알림이면 여기서 쓰지 않는다 — PR 본문 「## 팀원에게」에 쓴다(병합 뒤 더할 말은 미리의 총괄 대화창). 다른 창이 이미 보낸 메시지를 내가 붙여 넣으면 빠진 것만 짚는다. 보내기(카톡·메일)는 내가 한다.
4. **상태판에 적기**: `board.py set <이 대화창 폴더> --handoff "○○에게: 요점 한 줄"`. 내가 "보냈어"라고 하면 `board.py set <폴더> --sent`. 이 대화창에 폴더가 없으면(총괄 대화창 등) 관련 작업 줄에 적는다.
5. 코드를 고쳐야 하는 결론이 나면 여기서 고치지 않고 milwork 지시문을 남긴다(이 폴더 담당 파일이면 바로 고친다). 블록 위에 `<모델> · <effort>`, 블록 안은 첫 줄 `milwork <요청자> <제목>`과 둘째 줄 `모델: <모델> · <effort> (<고른 이유 한 마디>)` — 고르는 법은 milstart 4단계 「모델 고르기」.
- 요청자가 「상의」면 상의 대화창의 결론을 그대로 받아 반영한다. 결론과 다르게 고쳐야 할 이유가 보이면 고치기 전에 말한다.
- 폴더와 상태판 줄은 지우지 않는다. PR이 병합되면 하루 마무리(milend)가 지운다. 병합 뒤 정리 단계에는 `board.py queue done Q-n --pr <번호>` 한 줄로 큐 줄을 「완료」로 닫는다(완료 줄은 겹침 검사에서 빠진다).
- 작업이 끝나면 PR을 올리고 알린다. **vcc.me가 미리일 때만** "총괄 대화창에서 밀리뷰(검토)를 돌리세요"라고 한 줄 남긴다. 그 밖의 사람은 PR 병합·검토를 미리가 하니 PR 번호만 알린다. 이 대화창에서 **다른 작업을 이어 하려면 `milwork …`를 다시 친다**(폴더 안에서 브랜치를 갈아타지 않는다).

## 이 창을 닫아도 되나 (11/27 미리 — 끝 보고마다)
PR을 올린 뒤의 모든 답(PR 올림 보고, 검토 뒤 고침, `[병합]`·`[결정 D-n]` 받음)의 **맨 끝 줄**은 늘 아래 둘 중 하나다. 판정 근거는 실제로 본다(`git status`, `git log origin/<브랜치>..`, `gh pr view <n> --json state`, 돌고 있는 백그라운드 작업).
- 「**이 창: 닫아도 돼요** — PR #n 병합됨 · 큐 Q-n 완료」 — PR이 merged(총괄의 `[병합]` 메시지 또는 `gh`로 확인)이고, 안 올린 커밋·고친 파일·돌고 있는 작업·기다리는 결정(D-n)이 없을 때. 이때 `board.py queue done Q-n --pr <n>`을 먼저 한다(이미 완료면 건너뜀). 폴더 지우기는 milend가 한다.
- 「**이 창: 아직 닫지 마세요** — <이유 한 줄>」 — 예: 「PR #n 검토 대기(고칠 것이 오면 이 창에서 고침)」, 「안 올린 커밋 2개」, 「D-3 답 기다림」, 「측정 실행 중」.
PR 없이 끝난 일(조사만, 반려)은 「닫아도 돼요 — PR 없음 · 큐 Q-n 반려/완료」. 자세한 점검이 필요하면 `/ee`.

## 공통 규칙
파일 패치 스크립트는 Bash heredoc 대신 Write 도구로 만들어 실행한다. 폴더 삭제는 하지 않는다. 담당은 CLAUDE.md 「누가 무엇을 고치나」: `data/`·`tools/`·`functions/score.py`는 원우, `screens/`·`common/style.css`·`docs/design-rules.md`는 민지, `common/`·`functions/`는 미리. **내가 남의 담당 파일을 고칠 수 있는 건 vcc.me가 미리일 때뿐**이고, 그때는 미리 이름으로 고치는 것이니 PR 본문에 「○○ 요청으로 미리가 고침」을 적는다. 원우·민지는 자기 담당 밖 파일을 고치지 않고 담당자에게 PR 본문으로 요청한다.
