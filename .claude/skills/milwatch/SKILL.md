# milwatch — 총괄 점검 루프

총괄창 전용. 쓰는 법: 총괄창에서 **`/loop 20m /milwatch`**. 저장소를 고치지 않고, 새 작업도 시작하지 않는다(시작은 미리 — milstart 규칙 그대로).

규격 원본은 공통 부록(board.py 명령·세션 메시지 형식). 아래 `board.py`는 `python -X utf8 C:/dev/VCC/.claude/skills/milwork/board.py`. 상태판은 드라이브 `@VCC\총괄\board.md`(두 PC 공용).

## 한 번 돌 때 (순서대로, 바뀐 것만 보고)

### ① PR 메시지
- `gh pr list -R hufsiei/VCC --state open --json number,body,title`로 각 본문 「## 팀원에게」의 `[to미리]`·`[to전원]` 묶음을 읽는다.
- `~/.claude/vcc-milwatch-seen.json`(PR 번호 → 묶음 해시)에 없거나 해시가 바뀐 것만 보여 준다. 보여 준 뒤 이 파일에 기록한다(파일이 없으면 만든다).
- 묶음에 `(요청)`·`(결정요망)` 항목이 있으면 **「급함」**으로 표시한다.

### ② 큐 제안
`board.py queue`의 상태 「제안」 줄마다 본다.
- CLAUDE.md 「누가 무엇을 고치나」: 그 파일이 요청한 사람의 담당인가.
- `board.py check <파일들>`: 진행 중 줄과 겹치는가.
- 같은 작업 번호·같은 파일의 큐 줄이 중복인가.
- 문제 없으면 `board.py queue approve Q-n`. 겹치거나 담당이 아니면 **「보류」로 두고** 이유를 미리에게 보고한다(`queue reject`는 미리가 「반려」라고 말할 때만).
- `approve`가 종료코드 2로 겹침을 알려 오면 그 줄을 그대로 보고하고 보류한다.

### ③ 진행 겹침
- 상태판(`board.py list`)의 줄마다 `board.py check <그 줄 파일들> --me <폴더>`.
- `git -C C:/dev/VCC fetch -q` 뒤 각 줄의 브랜치마다 `git diff --name-only origin/main...origin/<브랜치>`로 **실제 바뀐 파일**을 모은다. 두 줄이 같은 파일을 건드리면 보고한다. 상태판에 적힌 파일과 실제가 다르면 그것도 보고한다. 브랜치를 아직 push하지 않았으면 「push 전」으로 두고 넘어간다.

### ④ 결정요망
`board.py decide`에서 답 없는 D-n을 번호·질문·선택지로 보여 준다.

### 보고
- 바뀐 것만, 한 건 한 줄. 지난 점검과 같은 줄은 다시 쓰지 않는다. 바뀐 것이 없으면 **「변화 없음」** 한 줄.
- 끝에 미리가 칠 수 있는 말을 한 줄로 적는다: `결정 D-n: A` · `승인 Q-n` · `반려 Q-n 이유` · `시작 Q-n`. 해당 건이 없는 말은 뺀다.

## 메시지 처리 (루프를 기다리지 않고 바로)
작업창에서 SendMessage가 오면(머리의 `[ ]`로 종류를 가린다) 바로 처리한다.
- `[제안 Q-n] <제목> — <예상 파일>` → ②를 그 건만 수행. 결과는 `[승인 Q-n]` 또는 `[보류 Q-n] <이유>`로 그 작업창 세션에 SendMessage(보낼 세션 이름은 큐 줄의 세션).
- `[결정요망 D-n] <질문> — <선택지>` → ④ 형식으로 미리에게 보여 준다. 미리가 `결정 D-n: A`라고 하면 `board.py decide answer D-n --a "A"`를 돌리고, 출력 첫 줄의 세션 이름으로 SendMessage `[결정 D-n] A`.
- `[PR #n] <슬러그> — <한 줄>` → 상태판 줄만 확인해 알린다(병합 판단은 milreview).
- `[막힘] <슬러그> — <한 줄>` → 미리에게 그대로 보고한다.
- 미리가 `시작 Q-n`이라고 하면 그 큐 줄로 `milwork 미리 <슬러그> <제목> Q-n` 지시문 **한 줄**을 만들어 보여 준다. 총괄창은 작업을 시작하지 않는다 — 미리가 새 대화창에 붙여 넣는다.
- 미리가 `승인 Q-n`이라고 하면 `queue approve`, `반려 Q-n 이유`라고 하면 `queue reject Q-n --why "이유"`.

## 지킬 것
- 세션 간 전달은 한 PC 안에서만. PC·사람 사이는 상태판·PR 본문으로 한다.
- 자동 배정 없음. 승인·보류까지만 하고 시작은 미리가 한다.
- 총괄 세션 이름이 상태판 머리와 다르면(`board.py chief`) 알리고 milstart의 `chief --set`을 다시 하라고 한다.
- 팀원에게 보낼 글이 필요하면 초안만 쓰고 보내지 않는다.
