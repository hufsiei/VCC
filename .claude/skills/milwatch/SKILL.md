# milwatch — 총괄 점검 루프

총괄창 전용. 쓰는 법: 총괄창에서 **`/loop 20m /milwatch`**. 저장소를 고치지 않고, 새 작업도 시작하지 않는다(시작은 내가 — milstart 규칙 그대로).

규격 원본은 공통 부록(board.py 명령·세션 메시지 형식). 아래 `board.py`는 `python -X utf8 C:/dev/VCC/.claude/skills/milwork/board.py`.

## 「나」는 누구인가
- `git config vcc.me`(원우|민지|미리). 없으면 `git config user.name`·`user.email`에 든 글자로 짐작한다(`.claude/skills/milwork/board.py`의 `who_am_i()`와 같은 방식). 모르면 한 번 묻고 `git config vcc.me <이름>`을 권한다.
- 이 글의 「나」는 모두 이 사람이다. 상태판·큐·결정은 사람별 파일(`board-<이름>.md`)이고 `board.py`가 자동으로 내 파일을 쓴다(명령은 그대로).
- **담당 검사는 CLAUDE.md 「누가 무엇을 고치나」를 나 기준으로 본다.** 예: 나=원우면 `data/`·`tools/`·`functions/score.py`는 내 것, `screens/<다른 화면>`·`functions/`(score.py 제외)는 남의 것.
- 다른 사람에게 보내는 요청·결정요망은 PR 본문 「## 팀원에게」(`[to이름]` 묶음)로 한다. SendMessage는 내 PC 안의 작업창과만 쓴다.
- 표시 「**미리만**」인 절은 `vcc.me`가 미리일 때만 한다. 아니면 건너뛴다.

## 한 번 돌 때 (순서대로, 바뀐 것만 보고)

### ① PR 메시지
- `gh pr list -R hufsiei/VCC --state open --json number,body,title`로 각 본문 「## 팀원에게」의 `[to<나>]`·`[to전원]` 묶음(여럿에게 간 `[to원우·민지]` 포함)을 읽는다.
- `~/.claude/vcc-milwatch-seen.json`(PR 번호 → 묶음 해시)에 없거나 해시가 바뀐 것만 보여 준다. 보여 준 뒤 이 파일에 기록한다(파일이 없으면 만든다).
- 묶음에 `(요청)`·`(결정요망)` 항목이 있으면 **「급함」**으로 표시한다.

### ② 큐 제안
`board.py queue`의 상태 「제안」 줄마다 본다.
- CLAUDE.md 「누가 무엇을 고치나」: 그 파일이 **나의** 담당인가. 남의 담당 파일이면 보류하고 그 사람에게 갈 요청을 PR 본문 「팀원에게」 초안으로 제안한다.
- `board.py check <파일들>`: 진행 중 줄과 겹치는가.
- 같은 작업 번호·같은 파일의 큐 줄이 중복인가.
- 문제 없으면 `board.py queue approve Q-n`. 겹치거나 담당이 아니면 **「보류」로 두고** 이유를 나에게 보고한다(`queue reject`는 내가 「반려」라고 말할 때만).
- `approve`가 종료코드 2로 겹침을 알려 오면 그 줄을 그대로 보고하고 보류한다.

### ③ 진행 겹침
- 상태판(`board.py list`)의 줄마다 `board.py check <그 줄 파일들> --me <폴더>`.
- `git -C C:/dev/VCC fetch -q` 뒤 각 줄의 브랜치마다 `git diff --name-only origin/main...origin/<브랜치>`로 **실제 바뀐 파일**을 모은다. 두 줄이 같은 파일을 건드리면 보고한다. 상태판에 적힌 파일과 실제가 다르면 그것도 보고한다. 브랜치를 아직 push하지 않았으면 「push 전」으로 두고 넘어간다.
- 열린 PR 중 남의 PR이 내 줄과 같은 파일을 바꾸면 그것도 보고한다(`gh pr list … --json number,files`).

### ④ 결정요망
`board.py decide`에서 답 없는 D-n을 번호·질문·선택지로 보여 준다.

### 보고
- 바뀐 것만, 한 건 한 줄. 지난 점검과 같은 줄은 다시 쓰지 않는다. 바뀐 것이 없으면 **「변화 없음」** 한 줄.
- 끝에 내가 칠 수 있는 말을 한 줄로 적는다: `결정 D-n: A` · `승인 Q-n` · `반려 Q-n 이유` · `시작 Q-n`. 해당 건이 없는 말은 뺀다.

## 메시지 처리 (루프를 기다리지 않고 바로)
작업창에서 SendMessage가 오면(머리의 `[ ]`로 종류를 가린다) 바로 처리한다.
- `[제안 Q-n] <제목> — <예상 파일>` → ②를 그 건만 수행. 결과는 `[승인 Q-n]` 또는 `[보류 Q-n] <이유>`로 그 작업창 세션에 SendMessage(보낼 세션 이름은 큐 줄의 세션).
- `[결정요망 D-n] <질문> — <선택지>` → ④ 형식으로 나에게 보여 준다. 내가 `결정 D-n: A`라고 하면 `board.py decide answer D-n --a "A"`를 돌리고, 출력 첫 줄의 세션 이름으로 SendMessage `[결정 D-n] A`.
- `[PR #n] <슬러그> — <한 줄>` → 상태판 줄만 확인해 알린다. 병합은 **미리만**(milreview, 병합 책임자). 나=미리가 아니면 PR 본문 「팀원에게」로 미리에게 `(요청)`을 넣을 것을 제안한다.
- `[막힘] <슬러그> — <한 줄>` → 나에게 그대로 보고한다.
- 내가 `시작 Q-n`이라고 하면 그 큐 줄로 milwork 지시문을 만들어 보여 준다. **블록 위에 `Q-n · <모델> · <effort>`**, 블록 안은 첫 줄 `milwork <나> <슬러그> <제목> Q-n`과 둘째 줄 `모델: <모델> · <effort> (<고른 이유 한 마디>)`(모델 고르는 법은 milstart 4단계 「모델 고르기」 그대로). 총괄창은 작업을 시작하지 않는다 — 내가 새 대화창을 그 모델로 바꾼 뒤 붙여 넣는다.
- 내가 `승인 Q-n`이라고 하면 `queue approve`, `반려 Q-n 이유`라고 하면 `queue reject Q-n --why "이유"`.

## 지킬 것
- 세션 간 전달은 한 PC 안에서만. PC·사람 사이는 상태판·PR 본문으로 한다.
- 자동 배정 없음. 승인·보류까지만 하고 시작은 내가 한다.
- 총괄 세션 이름이 상태판 머리와 다르면(`board.py chief`) 알리고 milstart의 `chief --set`을 다시 하라고 한다.
- 팀원에게 보낼 글이 필요하면 초안만 쓰고 보내지 않는다.
