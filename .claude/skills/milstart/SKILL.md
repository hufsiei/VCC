# milstart — 업무 시작

미리(VCC 총괄, PR 병합 책임자)를 위한 시작 루틴이다. 순서대로 하고, 6단계 전에는 저장소를 고치지 않는다.

## 1. 상태 확인 (조용히, 문제 있을 때만 말한다)
- 세션 맥락에 `[VCC] …` 한 줄(SessionStart hook)이 있으면 그 결과를 쓴다. 없으면 `python -X utf8 C:/dev/VCC/.claude/hooks/session_start.py`를 한 번 돌린다(그날 첫 실행이면 상태 한 줄이 나온다).
- `git -C C:/dev/VCC pull` 이 건너뛰어졌으면 이유(다른 브랜치·고친 파일)를 미리에게 알리고, 남의 작업일 수 있으니 임의로 되돌리지 않는다.
- `.env`: **값을 읽거나 출력하지 않는다.** 키 이름 3개(CLOVA_KEY·ANTHROPIC_API_KEY·VCC_LOGIN_PW)가 있는지만 본다. 모자라면 "Bitwarden에서 다시 붙여 주세요"라고만 말한다(.env 편집은 미리가 직접 한다).
- 계정: `gh auth status`의 활성 계정이 hufsiei인지, `git -C C:/dev/VCC config user.email`이 noreply 주소인지. 다르면 알린다.
- 남은 작업 폴더(`C:\dev\VCC-*`)가 있으면 어떤 브랜치인지·병합됐는지 확인해 정리할지 묻는다.

## 2. 자료 모으기
- 작업내역서: `H:\내 드라이브\@VCC\@VCC작업내역 v6.xlsx` (openpyxl, data_only, 읽기만). 시트 `작업목록`(번호·시기·단계·담당·기한·진행상황·비고·선행·막힌 점), `전달사항`(처리상태가 확인완료가 아닌 것), `주요링크`.
- git: 최근 병합 PR(`gh pr list -R hufsiei/VCC --state merged --limit 20`), 열린 PR, `git log --since` 어제.
- 팀 가이드: `주요링크` 시트의 팀 문서함 아티팩트를 Artifact `read`로 읽어 본다. 읽히지 않으면 "최신 팀 가이드를 붙여 넣어 주세요"라고 요청하고, 붙여 넣기 전까지는 작업내역서·git만으로 보고한다.
- 외부 요인: 메모리의 NCP 크레딧 상태 등.

## 3. 보고 (기술 용어 최소, 개념·의미 중심)
아래 세 부분만, 짧게.

**① 전체 흐름에서 어디까지 왔나** — 시기 단계(개발 1주 → 2주 → 통합 → 리허설 → 본선)별 완료 비율 표 1개 + 지금 단계의 의미 한두 문장. 예: "학생 쪽 기능이 서버까지 이어졌고, 이제 화면이 실제 서버를 쓰게 바꾸는 단계예요."

**② 정체된 곳** — 기한이 지났는데 진행중·시작 전인 일, 선행 작업에 막힌 일, 외부 요인(NCP 크레딧 등)에 묶인 일. 각 항목에 "그래서 무엇이 늦어지나"를 한 줄로.

**③ 오늘 미리가 할 일 3~5개** — 무엇을·왜. 세 묶음으로:
- 제가 혼자 할 수 있는 일(미리 개입 없음)
- 팀원과 맞춰야 할 일(누구와, 무엇을)
- 미리가 결정할 일(선택지와 추천)

기술적인 세부는 미리가 팀 가이드를 붙여 넣으며 따로 상의하므로 여기서 풀지 않는다.

## 4. 혼자 할 수 있는 일 시작
- 보고 끝에 "혼자 할 수 있는 일 ①부터 시작합니다"라고 말하고 바로 시작한다(미리가 막지 않으면).
- **AI 비용이 드는 일**(실제 AI 호출, 재분류, 측정)은 호출 수와 예상 금액을 먼저 말하고 승인받는다. 미리가 하루 비용 기준을 정하면 그 안에서는 묻지 않는다(기준이 정해지면 이 줄을 고친다).
- 병합은 미리 승인 뒤에만(`gh pr merge <n> --merge --admin`, hufsiei 계정).

## 작업 규칙 (늘 지킨다)
- 저장소를 고치기 전 `git -C C:/dev/VCC pull` → `git worktree add -b <브랜치> ../VCC-<이름> origin/main` → 그 폴더에서만 고친다 → PR.
- worktree에서도 `.env`·로그는 본 저장소 것을 쓴다(functions/paths.py). `.env`는 절대 읽어서 보여 주지 않는다.
- 파일 패치 스크립트는 Bash heredoc 대신 Write 도구로 파일을 만들어 실행한다(heredoc이 `\`를 망가뜨림).
- 폴더를 지울 때 셸이 그 폴더 안에 있으면 "Device or resource busy"로 실패한다. `cd /c/dev` 후 다시 `rm -rf`.
- `data/`·`tools/`는 원우, `screens/`·`style.css`·`design-rules.md`는 민지 담당. 고쳐야 하면 미리에게 먼저 말한다.
- 팀원에게 보낼 글이 필요하면 초안만 쓰고 보내지 않는다.
