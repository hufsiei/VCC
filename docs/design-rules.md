# 외대人사이드 (HUFS Inside) — 공통 UI 디자인 규칙 v4.0

> **v4.3 (2026-11-19, PRD v1.2·FDE 피드백)**: 노트 틀에 「후배 질문」 7번째 칸(5-7·7-①·7-②·8절), 들려주기는 질문함 질문을 먼저, 출처 칩은 연도만, 근거 적음·오래된 근거·자동 분류 라벨(6-1), 예시답 칩(P1-여건), 자소서용 요약 버튼 비활성, XSS 체크 항목(12절). 바뀐 곳은 **v4.3** 표시.

> **용도:** Claude Code(및 이미지 생성 도구)가 외대人사이드의 화면을 구현·수정하거나 시안 이미지를 만들 때 반드시 따르는 디자인 기준.
> **근거 문서:** 제출된 「외대人사이드 참가 신청서 및 아이디어 기획서」(이하 **기획서**). 화면 구성·메뉴명·용어·기능 범위는 모두 기획서를 따른다.
> **범위:** 이 문서는 **디자인 지침**이다. AI 동작, 권한, 데이터 구조, 추천 산식 등은 기획서 및 별도 기능 명세를 따른다. 시안의 예시 수치·콘텐츠를 실제 데이터로 간주하지 않는다.

## 0. 적용 원칙과 우선순위

1. **HUFS NAVY `#002D56`가 최상위 메인 컬러**다. 주요 CTA, 활성 메뉴, 제목, 핵심 아이콘은 모두 NAVY.
2. 화면 바탕은 흰색/연회색. 헤더를 네이비로 채우지 않는다.
3. 공통 UI(헤더·탭·CTA)는 모든 화면에서 같다. 화면마다 달라지는 색은 **콘텐츠·태그·요약 영역·상태 표시**에만 쓴다.
4. **닫힌 팔레트:** 3절 표에 있는 색만 쓴다. 표에 없는 색, 그라데이션, 임의 파스텔은 금지한다. **예외는 BOO 원본 이미지와 HUFS 심벌 원본 파일**뿐이다(두 자산의 색은 손대지 않는다).
5. 화면 문구와 메뉴명은 **1-2절 용어 표준**을 그대로 쓴다.
6. 충돌 시 우선순위: **기획서(기능·용어·범위) > 본 문서(디자인) > 기존 시안 이미지의 표현**. 모호하면 신규 기능을 임의로 만들지 않는다.

## 1. 서비스 개요와 용어 표준

### 1-1. 서비스 한 줄 정의 (기획서)

- **외대人사이드: Find someone who's been there**
- AI **BOO**가 선배 경험을 묻고 모아 노트로 쌓고(**모으기**), 궁금한 후배를 닮은 선배와 잇고(**잇기**), 학생 수요와 개선 사항을 부서로 전하는(**전하기**) MY HUFS 학생용 모듈.
- 다루는 경험은 **국제교류 · 현장실습 · 비교과** 세 가지다.

### 3-3. 분야별 컬러 (해봤노트 기준, 서비스 전체 공통)

| 분야 | 배경 (bg) | 글자·아이콘 (fg) | 포함 범위 | 대비 |

| **현장실습** | `#DDF2FC` | `#21698A` | 현장실습 학기제, 국내 인턴십(학점 인정), 특수외국어 체험형 현장실습 등 | 5.3:1 |

- 분류 기준은 **운영 경로(프로그램 소관)**다. 예: '국제교류·버디 활동'은 비교과 프로그램이므로 **비교과** 색을 쓴다.
- 같은 분야는 해봤노트 카드·상세·필터·닮은선배 경험 태그·내 보관함 등 **모든 곳에서 같은 색**이다.
- 분야색은 **카드 상단 띠, 분야 태그, 작은 아이콘 배경**에만 쓴다. 카드 본문은 흰색.
- 새 분류가 생기면 세 분야 중 하나에 넣는다. 네 번째 색을 자동으로 만들지 않는다.

### 3-4. 상태 컬러 (의미가 있을 때만)

| 상태 | bg | fg | 아이콘(필수) | 쓰는 곳 |
|---|---|---|---|---|
| 정보 | `#EAF3FA` | `#002D56` | ⓘ info | 안내 문구, '신규 수요' 라벨, 공식 안내 연결 |
| 긍정·완료 | `#E3F4EA` | `#1D6B43` | ✓ check | 저장 완료, 쪽지 수락됨 |
| 주의 | `#FDEBDD` | `#A14A0B` | ⚠ alert-triangle | 쪽지 실명·연락처 감지, '개선 요청'·'검토 필요' 라벨 |
| 오류·위험 | `#FDE8E8` | `#B42318` | ⊘ alert-circle | 전송 실패, 신고·차단, 입력 오류, 알림 점 |
| 중립 | `#F1F5F9` | `#475569` | (선택) | **수치 증감 배지 기본값**, 대기 상태 |

**규칙**
- 상태는 **색 + 아이콘 + 문구** 세 가지로 함께 표시한다. 색만으로 의미를 전달하지 않는다.
- **수치 증감(▲▼)은 기본적으로 중립색**으로 표시한다: `▲ 12% 전월 대비` (NEUTRAL bg + #475569).
  - 이유: 한국 금융 앱은 상승=빨강, 서구 대시보드는 상승=초록이라 방향색은 사람마다 반대로 읽힌다. 또 '질문 증가'처럼 좋고 나쁨이 정해지지 않은 지표가 대부분이다.
  - 기능 명세가 '좋은 방향'을 정한 지표만 긍정/오류 색을 쓴다(예: 미답변 질문 감소 → 긍정).
- 상태색과 분야색은 섞지 않는다. 분야 태그에는 아이콘을 넣지 않고, 상태 라벨에는 아이콘을 반드시 넣어 구분한다.

### 3-5. 금지

- 그라데이션 배경·버튼, 네온·형광색, 컬러 그림자.
- 분야색·상태색을 본문 텍스트 전체나 넓은 배경에 사용.
- 파스텔 배경 위 흰 글자, SILVER·DISABLED TEXT를 일반 텍스트로 사용.
- 화면마다 활성 탭 색을 바꾸는 것.

- 숫자는 `font-variant-numeric: tabular-nums`로 자릿수를 맞춘다.

### 4-2. 간격·모서리·그림자

- 간격 단위: **4 / 8 / 16 / 24 / 32px** (기본 8의 배수, 4는 아이콘-글자 사이 등 미세 조정용).

- 모서리: 카드 **12px**, 버튼·입력창 **12px**, 태그·칩 **999px(알약형)**, 말풍선 **16px**(꼬리 쪽 모서리 4px), 바텀시트 상단 **20px**.

### 4-3. 레이아웃

- 모바일 우선, 기준 폭 **375~430px**. PWA/데스크톱에서는 콘텐츠 최대 폭 **480px** 가운데 정렬, 바깥은 PAGE BACKGROUND.

- 터치 영역 최소 **44×44px**, 버튼 높이 **48px**.

## 5. 공통 컴포넌트

### 5-1. 메인 헤더 (1단계 화면)

```
[☰]        [심벌] 외대人사이드            [🔔•]     (직원 계정: [📊][🔔•])
```
- 배경 흰색, 하단 1px BORDER.
- 왼쪽: 햄버거 메뉴(내용은 기능 명세).
- 가운데: 심벌 + 워드마크(2-1).
- 오른쪽: **알림 버튼**. 학생 화면(시안 포함)에는 알림만 둔다.
  - **직원 계정일 때만** 알림 왼쪽에 관리자 콘솔 버튼을 더한다(PRD v1 4절): 막대 차트 픽토그램(`bar-chart-3` 계열), 24px, NAVY 선, `aria-label="관리자 콘솔"`. 누르면 PC 관리자 콘솔(`screens/admin/`)을 새 탭으로 연다. 순서는 [콘솔][알림].
  - 알림: 새 알림이 있으면 종 오른쪽 위 8px 점(오류색 `#B42318`, 흰 테두리 2px).

### 5-2. 화면 깊이와 상세 헤더 ⭐

**화면 깊이 규칙**

| 깊이 | 정의 | 헤더 | 하단 탭 |
|---|---|---|---|
| 1단계 | 하단 탭 4개 메뉴를 눌러 바로 나오는 첫 화면 (인터BOO, 해봤노트, 닮은선배, 내 보관함) | 메인 헤더(5-1) | **보임** |
| 2단계 이상 | 1단계 화면 안의 버튼·카드·목록 행·헤더 아이콘을 눌러 **새로 들어간 모든 화면** | 상세 헤더(아래) | **숨김** |

- 2단계 이상 예: AI 요약 미리보기, 해봤노트 상세, 선배 프로필, 익명 쪽지 대화, 내 경험노트 상세, 질문 상세, 알림 목록, 부서 리포트, 리포트 메일 미리보기.
- 2단계에서 다시 들어간 3단계 화면도 같은 규칙(상세 헤더 + 탭 숨김)을 따른다.
- **화면 이동이 아닌 것**은 탭을 그대로 둔다: 바텀시트·대화상자·토스트(화면 위에 덮임), 같은 화면 안의 상단 탭·필터·세그먼트 전환.
- 뒤로가기(←)를 누르면 들어오기 전 화면으로 돌아가고, 그 화면의 스크롤 위치·선택 탭을 유지한다.
- 2단계 화면의 주요 버튼은 화면 하단에 고정할 수 있다(하단 탭 자리 사용, 기기 안전 영역 포함).

**상세 헤더**

```
[←]   화면 제목(18px, 600)            [보조 아이콘]
```
- 흰 배경, 하단 1px BORDER, 높이 56px. 로고와 [리포트][알림] 버튼은 넣지 않는다.
- 보조 아이콘은 0~1개(예: 리포트 내려받기, 쪽지 ⋮ 메뉴).

### 5-3. 하단 탭

- 메뉴와 순서 고정: **인터BOO / 해봤노트 / 닮은선배 / 내 보관함**.
- 아이콘 24px + 라벨 12px.
- **활성:** SOFT BLUE `#EAF3FA` 알약형 배경 + NAVY 아이콘·글자 (모든 화면 동일. NAVY로 채운 배경 금지).
- **비활성:** 흰 배경 + TEXT MUTED `#64748B`.
- 2단계 이상 화면에서는 하단 탭을 표시하지 않는다(5-2).

### 5-4. 버튼

| 종류 | 배경 | 글자·아이콘 | 테두리 | 예 |
|---|---|---|---|---|
| 주요(Primary) | NAVY | WHITE | 없음 | 해봤노트에 공유, 쪽지 요청, 리포트 메일 발송 |
| 보조(Secondary) | SOFT BLUE | NAVY | 없음 | 내 보관함에 저장, 닮은선배 보기 |
| 외곽선(Outline) | WHITE | NAVY | 1px NAVY | 프로필 보기, 질문함에 담기 |
| 텍스트(Text) | 투명 | NAVY | 없음 | 전체 보기 ›, 취소 |
| 위험(Danger) | WHITE | `#B42318` | 1px `#B42318` | 차단, 신고 |
| 비활성 | NEUTRAL BG | DISABLED TEXT | 없음 | 실행 불가 |

- 한 영역에 Primary는 **1개**.
- 누름 상태: 배경을 8% 어둡게. 키보드 포커스: `2px` NAVY 외곽선 + 2px 간격.
- 비활성일 때는 **이유를 버튼 아래 14px 문구로** 알려준다(예: "첫 대화를 마치면 선배 추천이 열려요").

### 5-5. 카드

- 흰 배경, 12px 모서리, 그림자 또는 테두리 중 하나, 안쪽 여백 16px.
- 분야가 있는 카드: **상단 띠(높이 36~44px)에 분야 bg + 분야 태그 + 스크랩 버튼**, 아래는 흰 본문.

### 5-6. 태그·칩

| 종류 | 모양 | 색 |
|---|---|---|
| 분야 태그 | 알약형 높이 24px, 12px 600 | 3-3 분야 bg/fg, 아이콘 없음 |
| 키워드 칩(선택형) | 알약형 높이 32px, 14px | 기본: 흰 배경 + BORDER + CHARCOAL / 선택: NAVY 배경 + 흰 글자 |
| AI 키워드 | 알약형 24px | SOFT MINT + HUFS GREEN |
| 상태 라벨 | 알약형 24px, 아이콘 12px | 3-4 상태색 |

### 5-7. 노트 틀 진행 칩 (인터BOO 들려주기)

- 칩은 그 프로그램의 노트 틀(1-2절)을 따른다. 교환·파견은 일곱 칩 **지원 · 학점 · 비용 · 생활 · 팁 · 배운점 · 후배 질문**(v4.3). 가로 스크롤 허용.
- **후배 질문**(v4.3)은 질문함에 쌓인 후배의 미답변 질문을 BOO가 **가장 먼저** 묻는 칸이다. 질문 말풍선은 머리말 「후배가 이렇게 물었어요」 + 질문 원문(인용 스타일, SOFT BLUE 배경) + 「경험이 있으면 들려주세요」. 말풍선 아래 Text 버튼 **「경험이 없어요」**(건너뛰기 — 질문은 다른 선배에게 다시 나간다). 진행 칩의 「후배 질문」은 답하거나 건너뛰면 채워짐 처리. 질문함 질문 수는 `pendingQuestions`로 칩 옆 작은 배지 「후배 질문 1」.
- **예시답 칩**(v4.3, P1-여건): 서버가 `examples`를 주면 질문 말풍선 아래 Secondary 칩 2~3개(「출국 3학기 전」…). 탭하면 입력창에 그 글이 채워지고 사용자가 고쳐 쓴다. 바로 전송하지 않는다. 음성 입력은 만들지 않는다.
- **배운점**은 결과보고서 문항에 없는 칸이라 선배 인터뷰로만 채워진다. BOO는 인터뷰 마지막에 「이 경험이 지금의 나에게 뭘 남겼어요?」처럼 묻는다. 후배에게는 '할 만했는지'를, 본인에게는 자소서 재료를 준다.
- 상태 3가지:
  - 채워짐: SOFT MINT 배경 + HUFS GREEN 글자 + ✓
  - 지금 질문 중: NAVY 배경 + 흰 글자
  - 비어 있음: 흰 배경 + BORDER + TEXT MUTED
- 순서대로 진행하는 단계가 아니다. 근거가 적은 항목을 먼저 묻는다는 기획서 흐름이므로 번호(①②)를 붙이지 않는다.

### 5-8. 채팅

- AI 메시지(BOO): 흰 배경 + BORDER, 왼쪽에 BOO 36px 프로필, 위에 보낸 사람 이름 「BOO」(12px).
- 사용자 메시지: SOFT BLUE 배경, 오른쪽 정렬, 프로필 이미지 없음.
- 시간: 12px TEXT MUTED, 말풍선 아래.
- AI 입력 중: 흰 말풍선 안 점 3개 애니메이션.
- 입력창: 높이 48px, 흰 배경 + BORDER, 전송 버튼 40px 원형 NAVY(입력 전에는 비활성색).
- 이모지: AI 문장과 UI에 **기본적으로 쓰지 않는다**. 친근함은 BOO 이미지가 맡는다.

### 5-9. 입력창·폼

- 높이 48px, 12px 모서리, 흰 배경, BORDER.
- 포커스: 2px NAVY 테두리. 오류: 2px `#B42318` 테두리 + 아래 14px 오류 문구와 아이콘.
- 라벨은 입력창 위(14px 600). placeholder만으로 라벨을 대신하지 않는다.

### 5-10. 바텀시트·대화상자·토스트

- **바텀시트:** 동의·선택·필터에 사용. 상단 20px 모서리, 손잡이 막대, 하단에 Primary + Text 버튼.
  - 예: 해봤노트 공개 동의, 쪽지 요청 확인, 신고 사유 선택.
- **확인 대화상자:** 되돌릴 수 없는 동작(차단, 삭제)에만.
- **토스트:** 하단 탭 위 16px, CHARCOAL 배경 + 흰 글자, 3초 표시. 예: "질문함에 담았어요".

### 5-11. 아이콘

- **Lucide** 아이콘 세트(선형)로 통일. 선 굵기 **1.75px**, 끝 둥글게.
- 크기: 탭·헤더 24px, 본문 안 20px, 태그 안 12~14px.
- 색: 기본 NAVY 또는 TEXT MUTED. 분야·상태 아이콘만 해당 fg 색.
- 채운 아이콘, 3D, 이모지 아이콘은 쓰지 않는다.

## 6. 상태 패턴 (모든 화면 공통)

### 6-1. 근거/출처 블록 ⭐

기획서의 핵심 차별점("이수 기록으로 확인된 경험자의 답, 근거 표시")을 보여주는 공통 블록. **해봤노트 상세의 노트 틀 각 항목 아래**와 **인터BOO 물어보기 답변 아래**에 둔다.

```
┌ ✦ 근거 4건 · 결과보고서 2 · 선배 인터뷰 2 · 최근 2025-2학기   [펼치기 ▾] ┐
│  · 선배 인터뷰 | 2025                                                           │
│  · 결과보고서  | 2024                                                           │
└──────────────────────────────────────────────────────────────┘
```
- 배경 SOFT MINT, 아이콘·숫자 HUFS GREEN, 설명 CHARCOAL 14px.
- 출처 한 줄: 출처 종류 + **연도**(v4.3: `2024`처럼 학기 없이). 이름·학번·학과·입학년도는 넣지 않는다 — 노트가 프로그램 단위라 학과+연도만 보여도 소수 학과에서 사람이 특정될 수 있어 학과도 빼고, 머리줄의 「최근 2025-2학기」는 프로그램 집계값이라 학기까지 둔다.
- **근거 적음 라벨**(v4.3): 칸의 근거가 1~2건이면 머리줄 오른쪽에 중립 라벨 「선배 1명의 경험이에요」(2건이면 「선배 2명의 경험이에요」, 같은 선배면 1명). 보류하지 않는다.
- **오래된 근거**(v4.3): 칸의 근거가 모두 2년 넘은 연도이면 블록 아래 정보 라벨 「최근 경험이 없어요」 + Outline 「질문함에 담기」.
- **자동 분류 라벨**(v4.3): 현장실습 노트에서 `autoClassified: true` 문장은 출처 한 줄 끝에 작은 중립 라벨 「자동 분류」. 신고 버튼은 그대로.
- 학교 규정과 관련된 내용은 블록 아래에 **정보 라벨** "공식 안내 보기 ›"를 붙여 공식 안내로 연결한다.

### 6-2. 근거 없음 (0건)

- **틀은 그대로 두고 값만 비운다.**
```
┌ ✦ 근거 0건 · 결과보고서 – · 선배 인터뷰 – · 최근 –                            ┐
│  아직 이 항목을 경험한 선배의 이야기가 없어요.                                │
│  [질문함에 담기]  (외곽선 버튼)                                                │
└──────────────────────────────────────────────────────────────┘
```
- 배경은 SOFT MINT 대신 **NEUTRAL BG**, 숫자는 TEXT MUTED. "0건"은 숫자로, 나머지 값은 "–"로 표시한다.
- 인터BOO 물어보기에서 근거가 없으면 답을 지어내지 않는다. 위 블록 + "질문함에 담았어요" 토스트 + **닮은선배 보기**(보조 버튼)를 보여준다.

### 6-3. 로딩

- 목록·카드: **스켈레톤**(NEUTRAL BG 블록, 은은한 깜빡임). 스피너는 버튼 안 짧은 처리에만.
- AI 생성 중: 상태 라벨 「✦ 정리하는 중…」(SOFT MINT + HUFS GREEN). 생성 중인 영역에만 스켈레톤.

### 6-4. 빈 화면

- 구성: BOO 80px(또는 Lucide 아이콘 48px TEXT MUTED) → 18px 제목 1줄 → 14px 설명 1줄 → 버튼 1개.
- 예: 스크랩 없음 → "아직 담아둔 해봤노트가 없어요" / [해봤노트 둘러보기].

### 6-5. 오류

- 화면 안 오류: 오류 상태 라벨 + 문구 + [다시 시도](외곽선). 화면 전체를 빨갛게 칠하지 않는다.
- 네트워크 오류는 토스트로 짧게 알린다.

### 6-6. 잠김(조건 미충족)

- 기획서: "들려주기 또는 물어보기 초기 미션 완료 후에 선배 추천 버튼 활성화".
- 비활성 버튼 + 잠금 아이콘 + 조건 문구 14px. 숨기지 않고 보여 준다.

## 7. 대표 화면 6종 규칙

### ① 인터BOO

- 상단: 제목 「인터BOO」 + 설명 1줄 + BOO 안내 일러스트(오른쪽).
- 바로 아래 **들려주기 / 물어보기** 세그먼트(트랙 NEUTRAL BG, 선택된 쪽은 흰 알약 + NAVY 글자 + 그림자).
- **들려주기**: 노트 틀 진행 칩(5-7) → 채팅. **BOO는 질문함에 있는 후배 질문(「후배 질문」 칸, 최대 3개)을 먼저 묻고**(v4.3), 그 다음 근거가 적은 항목부터 묻는다. 첫 화면 안내 「후배 1명이 이 경험을 기다리고 있어요」(pendingQuestions가 1 이상일 때, 정보 라벨).
- **AI 요약 바 (들려주기 모드에만 표시)** — 입력창 바로 위에 고정:
  ```
  ┌ ✦ 노트 틀 3/6 채움                        [ ✦ AI 요약 ] ┐
  └──────────────────────────────────────────┘
  ```
  - 바: 높이 44px, SOFT MINT 배경, 12px 모서리, 좌우 여백 12px. 왼쪽 문구 HUFS GREEN 14px 600.
  - 버튼 「AI 요약」: 높이 32px 알약형, NAVY 배경 + 흰 글자 14px 600, ✦(sparkles) 아이콘.
  - 활성 조건: 노트 틀이 **1개 이상 채워졌을 때**. 0개이면 비활성(6-6) + 문구 「한 항목 이상 이야기하면 요약할 수 있어요」.
  - 누르면 **AI 요약 미리보기(2단계)** 로 이동한다. 대화를 끝내지 않아도 언제든 누를 수 있다.
  - 물어보기 모드에서는 표시하지 않는다(물어보기는 노트를 만들지 않음).
- **물어보기**: 채팅. BOO 답변 아래 **근거/출처 블록(6-1)** 과 관련 해봤노트 카드 링크. 근거가 없으면 6-2.
- 설명 문구 예: 들려주기 "BOO에게 경험을 들려주면 노트로 정리해 드려요." / 물어보기 "선배들의 해봤노트를 근거로 답해 드려요."

### ② AI 요약 미리보기 (들려주기 결과, 2단계)

- 진입: 인터BOO의 **AI 요약 바 → 「AI 요약」**. 상세 헤더(← AI 요약 미리보기), **하단 탭 숨김**.
- 흐름(기획서: 대화 주제화·요약 → 내 경험노트 → 본인 동의 시 해봤노트 작성). **저장은 기본, 공유는 선택** (v4.1):
  ```
  인터BOO 대화 → [AI 요약] → 요약 완료 = 내 경험노트에 자동 저장(나만 보기)
                                   ├→ [해봤노트에 공유] → 공개 동의 시트(문장별 켜기/끄기) → 해봤노트 반영
                                   └→ [나중에 할게요] → 내 보관함 · 내 경험노트 탭 (언제든 상세에서 공유 가능)
  ```
  - 사용자가 '저장'과 '공유' 중 하나를 고르는 구조가 아니다. 요약이 끝나면 항상 내 경험노트에 남고, 공유는 그 위에 더하는 행동이다.
- 상단: BOO 안내(80px) + 상태 라벨 「✦ 대화 정리하는 중…」 → 완료 시 「✓ 요약 완료 · 내 경험노트에 저장됨」(긍정 라벨, lock 아이콘 없이 check).
- 요약 카드: 머리 띠 SOFT MINT + HUFS GREEN 아이콘 + 「(프로그램명) 경험노트 (요약 초안)」, 본문 흰색. 이 카드는 **내 경험노트 원본**이며, 해봤노트에는 공개 동의한 문장만 들어간다.
- 본문 항목은 **노트 틀 순서(교환·파견: 지원·학점·비용·생활·팁·배운점·후배 질문)** 로 정리. 아직 이야기하지 않은 항목은 "–"로 둔다(6-2와 같은 원칙). 인턴·비교과는 각자의 노트 틀(1-2절) 순서. **후배 질문** 항목은 Q(후배 질문 원문, 인용 스타일) + A(내 답) 쌍으로 보인다(v4.3).
- 이 화면에는 해봤노트 관련 블록을 두지 않는다(v4.1). 화면 = 내 경험노트, 해봤노트 = 공유했을 때의 결과이므로 결과는 공개 동의 시트에서 보여 준다. 요약 카드가 그만큼 화면을 넓게 쓴다.
- 하단 고정 버튼:
  - Primary 「해봤노트에 공유」 → **공개 동의 바텀시트**(아래).
  - Secondary 「나중에 할게요」 → 내 보관함 · 내 경험노트 탭으로 이동 + 토스트 「내 경험노트에 저장돼 있어요. 언제든 공유할 수 있어요」.
  - Text 「대화 이어가기」 → 인터BOO로 돌아감(같은 경험노트에 이어서 채움).
- **공개 동의 바텀시트** (문장 단위 동의, v4.1), 위에서 아래 순서:
  - **① 「반영될 해봤노트」 블록** (시트 맨 위): 내 이야기가 어느 해봤노트에 합쳐지는지 보여 준다.
    - 같은 프로그램 노트가 있을 때: 분야 태그 + 노트명 + 「근거 6건 → 7건」(HUFS GREEN) + 14px 안내 「결과보고서·다른 선배 인터뷰와 함께 정리돼요」.
    - 없을 때: 정보 라벨 「새 해봤노트로 만들어져요」.
    - 흰 카드 + BORDER. 분야색은 태그에만. 근거 수의 '→ N건'은 아래에서 켠 문장이 하나도 없으면 바뀌지 않는다(0개면 「동의하고 공유」 비활성).
  - **② 문장 목록**: 노트 틀 칸별로 요약 문장을 나열하고, **문장마다 공개 스위치**(기본 켬)를 둔다. 끈 문장은 내 경험노트에만 남는다.
  - 본인이 드러나는 문장(성적·수상·실명·특정 인물 등)은 코드가 찾아 **기본 꺼짐**으로 두고 주의 라벨 「나를 알아볼 수 있는 내용이에요」를 붙인다. 판단은 사용자가 한다.
  - **③ 두 목록**: 공개되는 것(켠 문장, 전공, 이수 학기) / 공개되지 않는 것(이름, 학번, 대화 원문, 끈 문장).
  - **④** 동의 체크 후 Primary 「동의하고 공유」.
  - 시트가 길어지므로 최대 높이 화면의 85%, 안쪽 스크롤, 「동의하고 공유」는 시트 하단 고정.
- 공유 후 상태: 토스트 「해봤노트에 반영하고 있어요」 → 반영이 끝나면 알림 「해봤노트에 내 이야기가 반영됐어요」 + 해봤노트 상세 링크. 반영 전까지 내 경험노트 카드에 중립 라벨 「반영 중」. **후배 질문에 답한 문장이 공유되면 그 후배에게 알림 「내 질문에 선배가 답했어요 · ○○ 해봤노트」가 간다**(v4.3, 선배 화면에는 표시 없음).
- RAG 합성, 출처 매칭, 검토 후 게시 여부 등 AI·운영 동작은 기능 명세를 따른다. 이 문서는 화면 상태만 정한다.
- 녹색은 'AI가 정리한 내용'의 표시색일 뿐, CTA는 NAVY.

### ③ 해봤노트 (목록)

- 상단: 제목 + 설명 + **채팅형 검색창**(「BOO에게 물어보기」, 누르면 인터BOO 물어보기로 이동).
- 필터 칩: 전체 / 국제교류 / 현장실습 / 비교과 + AI 키워드 칩(자동 생성, 질문량 순).
- **노트 카드(커버)** — 1열 목록을 기본으로 한다:
  - 상단 띠: 분야 태그 + 세부 분류(예: 교환학생 · 독일) + 스크랩 버튼
  - 프로그램명(18px)
  - 한 줄 요약(16px, 최대 2줄)
  - 추천 대상(14px, 예: "독일어 전공 2~3학년")
  - 메타 줄: `근거 4건 · 최근 2025-2학기 · ★ 4.5` (별은 GOLD)
- 사진은 기본으로 쓰지 않는다. 썸네일이 필요하면 **분야 bg 정사각형 + 분야 fg 선형 아이콘**을 쓴다. 실제 사진은 저작권이 확인된 제공 이미지일 때만 쓴다.

### ④ 닮은선배

- 상단: 제목 + 설명("내가 궁금한 경험을 해본 선배 중, 출발점이 비슷한 선배를 추천해요.") + BOO.
- 「나의 프로필 요약」 카드: SOFT BLUE 배경, 소속 학과·학년·관심 경험(분야 태그).
- 추천 목록 제목: 「추천 선배 N명」 — **N은 실제 표시 카드 수와 같아야 한다.**
- 추천 인원과 더 보기(v4.2, 11/18):
  - 화면에 들어오면 서버가 준 상위 **3명**이 바로 보인다. 첫 추천을 버튼 뒤에 숨기지 않는다.
  - 목록 아래 Secondary 버튼 **「선배 더 보기」**. 누르면 다음 3명이 **아래에 누적**되고 기존 카드는 자리·글자(A, B, C…)가 바뀌지 않는다. 제목의 N도 함께 늘어난다.
  - 총 **9명**이 상한. 서버 응답 `hasMore`가 `false`면(9명에 닿았거나 후보가 없음) 버튼 자리에 빈 상태 문구 **「비슷한 선배를 모두 보여드렸어요」**(TEXT MUTED, 14px, 가운데)를 둔다. 비활성 버튼으로 두지 않는다.
  - 날짜·횟수 제한 UI(쿨다운, "N일 뒤 다시")는 만들지 않는다. 제한은 인원과 점수가 한다.
  - 재추천(P1): `newCount`가 1 이상이면 제목 옆 배지 「새로 비슷한 선배 N명」, `recomputed`면 상단 안내 「내 기록이 바뀌어 다시 추천할 수 있어요」. 이 둘일 때만 「선배 더 보기」가 다시 나온다.
- 선배 카드:
  - 중립 아바타(원형 40px, NEUTRAL BG + TEXT MUTED 사람 아이콘). 인물 사진·인물 일러스트는 쓰지 않는다.
  - 표시명: **「학과 + 선배 + 영문 대문자」** (예: 독일어과 선배 A). 성·이름·**학번(입학년도)**은 쓰지 않는다(기획서: 이력 비식별, 익명 쪽지). 학과와 입학년도가 함께 보이면 같은 학과 학생이 사람을 특정하기 쉽기 때문이다(v4.1). 글자는 서버가 정하는 `nickname`이며, 같은 사용자에게는 카드·프로필·쪽지창에서 늘 같다.
  - 경험 태그: **분야색(3-3)** 사용.
  - 추천 이유 1줄: SOFT MINT 아이콘 + HUFS GREEN ✦ + CHARCOAL 14px (AI가 쓴 문장임을 표시).
  - 추천 순위·일치 표시: 일치 항목(관심 경험 · 전공 · 단과대 · 비교과)을 칩으로 보여 준다. **매칭률 %는 기능 명세에 산식이 확정된 경우에만** 표시한다.
  - 버튼: Outline 「프로필 보기」 + Primary 「쪽지 요청」.
- 미션 전에는 6-6 잠김 상태.

### ⑤ 부서 리포트 (v4.1: 학생 앱 화면이 아님 — PC 관리자 콘솔의 '리포트 미리보기(메일 본문)' 레이아웃으로 사용, PRD v1 5절)

- 상세 헤더(5-2) + 하단 탭 숨김. BOO 사용 안 함. 장식색 최소화.
- 상단: 기간 선택(예: 2025-2학기 ▾) + 부서 선택.
- 지표 카드 2×2: 흰 카드 + 아이콘(NAVY) + 지표명 14px + 수치 28px + **증감 배지(중립색, ▲▼ + % + "전월 대비")**.
  - 지표는 기획서 범위에서 고른다: **질문 수 / 미답변 질문 / 신규 수요 / 개선 요청**.
- 「프로그램별 질문 순위」: 막대 목록(막대는 NAVY 단색, 값 라벨 표시).
- 「주요 인사이트」 목록: 각 행에 분야 아이콘 썸네일 + 제목 + 상태 라벨(신규 수요=정보, 개선 요청=주의, 검토 필요=주의).
- 하단 Primary 「리포트 메일 발송」 → 받는 사람·미리보기 바텀시트 → 발송 완료 토스트.

### ⑥ 내 보관함 (1단계)

- 메인 헤더 + 하단 탭(내 보관함 활성).
- 상단: 제목 「내 보관함」 + 설명 「내 경험노트, 질문, 담아 둔 해봤노트를 모아 봐요.」 + 정보 라벨 「🔒 나만 보기」(lock 아이콘, 이모지 아님). BOO는 빈 화면에서만.
- **상단 탭 3개: 내 경험노트 / 질문함 / 스크랩** (각 이름 옆 개수 14px).
  - 활성: NAVY 글자 600 + 아래 2px NAVY 밑줄. 비활성: TEXT MUTED. 탭 영역 하단 1px BORDER.
  - 새 소식(답변 도착 등)이 있는 탭은 이름 오른쪽 위에 6px 오류색 점.
  - 탭 전환은 같은 화면 안의 전환이므로 하단 탭은 그대로 보인다(5-2).
- **내 경험노트 탭**: 경험노트 카드 = 분야 띠(태그 + 프로그램) + 노트명 + 「노트 틀 3/6」 + 공유 상태 라벨(나만 보기=중립, 반영 중=중립, 해봤노트 공유됨=긍정, 일부 공유=중립 「N문장 공유」) + Secondary 「자소서용 요약 보기」. 카드를 누르면 내 경험노트 상세(2단계).
  - 인터뷰를 한 번이라도 요약한 사용자는 이 탭이 비지 않는다(저장은 기본).
  - **자소서용 요약**: 같은 경험노트에서 만든다. 배운점 칸 + 지원·활동 사실을 1인칭 문장으로 바꿔 보여 주며, 공개하지 않은 문장도 쓴다(나만 보기). 해봤노트용 문장과 원본은 같고 쓰임만 다르다.
- **질문함 탭**: 질문 카드 목록. 정렬은 「답변 도착」이 맨 위.
  - 카드 구성: 상태 라벨 + 질문 문장(16px 600, 최대 2줄) + 남긴 날짜(12px) + 연결 정보 + 버튼.
  - 상태 라벨: 대기 중=중립(clock), 답변 도착=긍정(check), 공식 안내=정보(info).
  - 답변 도착: 연결 정보 「라이프치히대학교 교환학생 해봤노트에 새 근거가 생겼어요 · 근거 6→7건」 + Primary 「해봤노트 보기」 + Outline 「닮은선배 보기」.
  - 대기 중: 「근거 0건 · 선배 인터뷰 질문으로 전달됐어요」(6-2 표기) + 버튼 없음 또는 Text 「질문 삭제」.
  - 공식 안내: 규정·절차 질문 → 정보 라벨 + 「공식 안내 보기 ›」.
- **스크랩 탭**: 해봤노트 카드(7-③과 같은 컴포넌트), 스크랩 아이콘은 채운 상태.
- 각 탭이 비어 있으면 6-4 빈 화면.

## 8. 세부 화면 확장 규칙 (향후 구현 시 동일 적용)

> 아래 화면은 기획서에 기능이 있으나 대표 화면(7절)에는 없는 화면이다. 모두 2단계 이상이므로 **상세 헤더 + 하단 탭 숨김**(5-2)을 따른다. 새 컴포넌트를 만들지 말고 5·6절 컴포넌트를 조합한다.

| 세부 화면 | 사용 패턴 | 색·자산 |
|---|---|---|
| 선배 프로필 | 상세 헤더 → 중립 아바타 + 「학과 + 선배 + 영문 대문자」 → 경험 태그(분야색) → 추천 이유 → 하단 고정 Primary 「쪽지 요청」 | 분야색 + MINT |
| 해봤노트 상세 | 상세 헤더 → 커버(분야 띠 + 5항목) → 노트 틀 탭(지원·학점·비용·생활·팁·배운점·**후배 질문**) → 항목별 문장 + 근거/출처 블록(6-1/6-2). **배운점 칸은 여러 선배 문장을 합쳐 요약하지 않고 선배별 원문 인용**(「독일어과 선배 A」 + 문장)으로 보여 준다. **후배 질문 칸(v4.3)**: 질문 하나가 카드 하나 — 위에 「Q」 + 후배 질문 원문(SOFT BLUE 인용 스타일, 질문자 정보 없음), 아래에 「A」 + 선배 답 문장(원문 인용) + 출처 칩(선배 인터뷰 · 연도). 같은 질문에 답이 여럿이면 A가 아래로 쌓인다. 비어 있으면 6-2(「아직 후배 질문에 답한 선배가 없어요」). 본문 문장은 사전 생성 노트의 **원문 인용**이고 칸 요약 한 줄은 서버가 줄 때만(P1-여건) → "이 노트 경험자 중 닮은선배" 카드 | 분야색 + MINT(근거) |
| 인터BOO 물어보기 답변 | 채팅 + 근거 블록 + 관련 노트 카드 링크 + 근거 없음 처리 | SOFT BLUE / MINT |
| 내 경험노트 상세 | 본인만 열람 표시(🔒 + "나만 보기" 정보 라벨), 노트 틀 요약(공유한 문장에는 작은 긍정 라벨 「공유됨」), 「자소서용 요약 보기」 Secondary(**v4.3: 이번 범위에서는 비활성(6-6) + 문구 「운영 연계 시 열려요」**), 「해봤노트에 공유」 Primary(이미 공유했으면 「공유 범위 바꾸기」) | MINT |
| 질문 상세 | 질문 문장 + 상태 라벨(「답을 기다려요」/「선배가 답했어요」) + 관련 해봤노트 근거 블록(6-1/6-2) + **답했으면 「후배 질문」 칸의 A 문장과 「해봤노트에서 보기」 링크**(v4.3) + 닮은선배 추천 | 상태색 + MINT |
| 알림 목록 | 상세 헤더, 행 = 아이콘 + 문장 + 시간, 안 읽은 알림은 SOFT BLUE 배경 | SOFT BLUE |
| 익명 쪽지 요청 (보내는 쪽) | 바텀시트: 요청 문장 입력 + 내 닉네임 안내 정보 라벨 「선배에게는 '용감한 수달'로 보여요」(닉네임은 시트를 여는 순간 서버가 만든 값) + 안내("선배가 수락하면 대화가 열려요") + Primary 「쪽지 요청」. **한도(v4.2)**: 기다리는 요청이 3건이면 시트를 열지 않고 카드의 「쪽지 요청」 자리에 안내 「답을 기다리는 쪽지가 3건이에요 · 기다리는 요청 보기」(링크 → 내 보관함 쪽지). 이미 요청한 선배의 카드는 「요청 보냄」(비활성)으로 바꾼다 | NAVY + 정보색 |
| 기다리는 요청 (보낸 쪽, 내 보관함 쪽지 목록) | 상태 라벨 「수락 대기」 + Outline **「요청 취소」**(확인 바텀시트: "취소하면 이 선배에게는 7일 뒤에 다시 요청할 수 있어요"). 취소 뒤 상태 라벨 「취소함」, 만료 뒤 「응답 없음」(둘 다 NEUTRAL, 목록 맨 아래로). 만료 알림 「선배가 아직 못 봤어요. 다른 선배에게 보내 볼까요?」 + Outline 「닮은선배 보기」 | 중립색 |
| 받은 쪽지 요청 (선배 쪽) | 알림 「쪽지 요청이 왔어요」 → 요청 카드: 「용감한 수달 · 1학년 · 관심: 교환학생·독일」 + 요청 문장 + Primary 「수락」 / Outline 「거절」. **학과는 보이지 않는다**(학과 + 학년이 함께 보이면 사람을 특정하기 쉬움) | NAVY |
| 익명 쪽지 대화 | 상세 헤더 + 채팅 컴포넌트. 상대 이름은 **보는 사람에 따라 다르다**: 보낸 후배 화면 = 「독일어과 선배 A」, 받은 선배 화면 = 「용감한 수달」. 메뉴 ⋮: 신고·차단. 실명·연락처·욕설 감지 시 입력창 위 **주의 라벨** + 문구 | 주의·오류색 |
| 공개 동의 | 바텀시트: 「반영될 해봤노트」 블록(맨 위) + 칸별 문장 + 문장마다 공개 스위치(본인 식별 문장은 기본 꺼짐 + 주의 라벨) + 공개되는 것/공개되지 않는 것 목록 + 체크박스 + Primary (7-② 참조) | NAVY + 주의색 |
| 첫 진입(온보딩) | 들려주기/물어보기 선택 카드 2개 + 이력 확인 카드 + 미션 진행 표시 | NAVY + BOO |
| 오픈배지·마일리지(확장) | 배지 아이콘·점수에만 GOLD | GOLD |

## 9. 데이터·콘텐츠 표기

- 대회 기간 화면에는 **가상 데이터만** 쓴다(`외대人사이드_가상학생_1000명.xlsx`). 실제 명단·원문을 쓰지 않는다.
- 학생·선배 이름과 학번(입학년도 포함)을 화면에 쓰지 않는다. 표시는 "학과 + 선배/후배 + 영문 대문자"(예: 독일어과 선배 A).
- 학과명은 가상학생 파일의 학과(전공) 표기를 그대로 쓴다(예: 독일어과, 스칸디나비아어과, 프랑스어학부 FATI전공).
- 국가·대학명은 가상학생 파일의 파견국가·파견대학 값을 쓴다.
- 수치(질문 수, 만족도 등)는 서로 맞아야 한다. 예: "추천 선배 3명"이면 카드 3개.
- 화면 문구에 오탈자가 없어야 한다. 배포 전 1-2절 용어 표준과 대조한다.

## 10. 시안 이미지 생성 규칙 (배너·목업)

### 10-1. 원칙

1. **색은 3절 닫힌 팔레트의 HEX만** 쓴다. 이미지 생성 프롬프트에 HEX를 직접 적고 "이 외의 색 사용 금지"를 명시한다.
2. **BOO와 HUFS 심벌은 생성하지 않는다.** 원본 파일을 합성(붙여넣기)한다. 생성 도구가 합성을 지원하지 않으면 그 자리를 빈 흰 원으로 두고 편집 단계에서 원본을 넣는다.
3. 사진·인물 일러스트를 생성하지 않는다(7-③, 7-④ 규칙과 동일).
4. 모든 한글 문구는 **이 문서의 문구를 그대로 복사**해 넣는다. 생성 결과의 글자는 반드시 검수한다.
5. 가능하면 **HTML 목업 → 스크린샷** 방식으로 만든다. 색·글자·자산을 정확히 지킬 수 있다.

### 10-2. 프롬프트 템플릿

```

허용 색상(이 외 금지): #002D56, #146E7A, #8D7150, #FFFFFF, #F7F9FC, #EAF3FA, #D5F0E1,
#334155, #64748B, #E2E8F0, #F1F5F9, #FFF2CD/#9B6100, #DDF2FC/#21698A, #DFF3E7/#246D51.

캐릭터와 로고 자리는 빈 흰색 원으로 둘 것.

```

### 10-3. 생성 후 검수

- [ ] 팔레트 밖 색이 없는가(특히 캐릭터 주변 장식, 태그, 그래프)
- [ ] BOO·심벌이 원본 파일인가
- [ ] 메뉴명이 「인터BOO」인가, 탭 활성 표시가 화면과 맞는가
- [ ] 문구 오탈자, 숫자 불일치가 없는가
- [ ] 분야 태그가 국제교류/현장실습/비교과 3종과 지정색인가
