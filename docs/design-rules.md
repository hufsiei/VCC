## 0. 적용 원칙과 우선순위

1. **HUFS NAVY `#002D56`가 최상위 메인 컬러**다. 주요 CTA, 활성 메뉴, 제목, 핵심 아이콘은 모두 NAVY.
2. 화면 바탕은 흰색/연회색. 헤더를 네이비로 채우지 않는다.
3. 공통 UI(헤더·탭·CTA)는 모든 화면에서 같다. 화면마다 달라지는 색은 **콘텐츠·태그·요약 영역·상태 표시**에만 쓴다.
4. **닫힌 팔레트:** 3절 표에 있는 색만 쓴다. 표에 없는 색, 그라데이션, 임의 파스텔은 금지한다. **예외는 BOO 원본 이미지와 HUFS 심벌 원본 파일**뿐이다(두 자산의 색은 손대지 않는다).
5. 화면 문구와 메뉴명은 **1-2절 용어 표준**을 그대로 쓴다.
6. 충돌 시 우선순위: **기획서(기능·용어·범위) > 본 문서(디자인) > 기존 시안 이미지의 표현**. 모호하면 신규 기능을 임의로 만들지 않는다.

- 상태는 **색 + 아이콘 + 문구** 세 가지로 함께 표시한다. 색만으로 의미를 전달하지 않는다.
- **수치 증감(▲▼)은 기본적으로 중립색**으로 표시한다: `▲ 12% 전월 대비` (NEUTRAL bg + #475569).
  - 이유: 한국 금융 앱은 상승=빨강, 서구 대시보드는 상승=초록이라 방향색은 사람마다 반대로 읽힌다. 또 '질문 증가'처럼 좋고 나쁨이 정해지지 않은 지표가 대부분이다.
  - 기능 명세가 '좋은 방향'을 정한 지표만 긍정/오류 색을 쓴다(예: 미답변 질문 감소 → 긍정).
- 상태색과 분야색은 섞지 않는다. 분야 태그에는 아이콘을 넣지 않고, 상태 라벨에는 아이콘을 반드시 넣어 구분한다.

### 3-5. 금지

- 그라데이션 배경·버튼, 네온·형광색, 컬러 그림자.
- 분야색·상태색을 본문 텍스트 전체나 넓은 배경에 사용.
- 파스텔 배경 위 흰 글자, SILVER·DISABLED TEXT를 일반 텍스트로 사용.
- 화면마다 활성 탭 색을 바꾸는 것.

### 5-7. 노트 틀 진행 칩 (인터BOO 들려주기)

- 칩은 그 프로그램의 노트 틀(1-2절)을 따른다. 교환·파견은 여섯 칩 **지원 · 학점 · 비용 · 생활 · 팁 · 배운점**(11/25 v2 — 「후배 질문」 칩 없음). 가로 스크롤 허용.
- **후배 질문 먼저 묻기**: BOO는 질문함에 쌓인 후배의 미답변 질문을 **가장 먼저** 묻는다(서버 `junior: true`). 질문 말풍선은 머리말 「후배가 이렇게 물었어요」 + 질문 원문(인용 스타일, SOFT BLUE 배경) + 「경험이 있으면 들려주세요」. 말풍선 아래 Text 버튼 **「경험이 없어요」**(건너뛰기 — 질문은 다른 선배에게 다시 나간다). 그동안 진행 칩은 **그 질문이 속한 칸**이 「지금 질문 중」이고, 답하면 그 칸이 채워진다. 남은 후배 질문 수(`pendingQuestions`)는 지금 칩 옆 작은 배지(숫자).
- **예시답 칩**(v4.3, P1-여건): 서버가 `examples`를 주면 질문 말풍선 아래 Secondary 칩 2~3개(「출국 3학기 전」…). 탭하면 입력창에 그 글이 채워지고 사용자가 고쳐 쓴다. 바로 전송하지 않는다. 음성 입력은 만들지 않는다.
  - **(11/26, #331-2) 물어보기 「궁금한 것 정리하기」의 직접 쓰는 단계**(지금 내 상황·얻고 싶은 것 등): 같은 말풍선의 고르는 칩과 모양이 같아 선택지로 보이므로, 칩 위에 안내 한 줄(pencil 16px + 14px TEXT MUTED) 「아래 입력칸에 직접 써 주세요. 예시를 누르면 채워져요」를 두고 칩 글자 앞에 「예: 」를 붙인다. 고르는 칩은 그대로.
- **배운점**은 보고서 문항에 없는 칸이라 선배 인터뷰로만 채워진다. BOO는 인터뷰 마지막에 「이 경험이 지금의 나에게 뭘 남겼어요?」처럼 묻는다. 후배에게는 '할 만했는지'를, 본인에게는 자소서 재료를 준다.
- 상태 3가지:
  - 채워짐: SOFT MINT 배경 + HUFS GREEN 글자 + ✓
  - 지금 질문 중: NAVY 배경 + 흰 글자
  - 비어 있음: 흰 배경 + BORDER + TEXT MUTED
- 순서대로 진행하는 단계가 아니다. 근거가 적은 항목을 먼저 묻는다는 기획서 흐름이므로 번호(①②)를 붙이지 않는다.

- AI 입력 중: 흰 말풍선 안 점 3개 애니메이션. **(11/27, #364) 물어보기**에서 3초가 지나도 답이 없으면 점 옆에 중립 라벨 「선배 글을 읽고 있어요 · 보통 5초 걸려요」(clock). 코드 문구라 AI 색이 아니다. 「N건」 숫자는 넣지 않는다(응답 전에 알 수 없음).
- 입력창: 높이 48px, 흰 배경 + BORDER, 전송 버튼 40px 원형 NAVY(입력 전에는 비활성색).
- **휴대폰 키보드(11/26, 11/27 #363 고침)**: 키보드가 열려 화면이 줄어든 동안 하단 탭을 숨기고 입력줄을 키보드 바로 위에 붙인다 — 화면 이동이 아니라 키보드 때문에 잠깐 비키는 것(5-2 예외). 본문 아래 여백도 그만큼 늘려 마지막 말풍선까지 내려 볼 수 있게 하고, 전송 버튼을 눌러도 키보드는 닫지 않는다. 키보드가 닫히면 하단 탭이 돌아온다. 기다리는 동안(BOO 답 대기)에도 입력창은 켜 두고 전송만 막는다. PC는 바뀌지 않는다.
- **맨 위로(11/25)**: 대화를 한 화면 넘게 내리면 고정 입력줄 바로 위 오른쪽(8px 위, 오른쪽 12px)에 44px 원형 버튼 — 보조 버튼 색(SOFT BLUE + NAVY `arrow-up-to-line` 20px), 그림자는 카드와 같음, `aria-label="맨 위로"`. 누르면 화면 맨 위로(움직임 줄이기 설정이면 바로). 맨 위 한 화면 안에서는 숨긴다. 전송 버튼(↑)과 헷갈리지 않게 아이콘은 `arrow-up`이 아니라 `arrow-up-to-line`.
- 이모지: AI 문장과 UI에 **기본적으로 쓰지 않는다**. 친근함은 BOO 이미지가 맡는다.

### 5-9. 입력창·폼

- 높이 48px, 12px 모서리, 흰 배경, BORDER.
- 포커스: 2px NAVY 테두리. 오류: 2px `#B42318` 테두리 + 아래 14px 오류 문구와 아이콘.
- 라벨은 입력창 위(14px 600). placeholder만으로 라벨을 대신하지 않는다.
- **여러 줄 입력창(11/25)**: 문장 고치기(7-②·8절 내 경험노트 상세)·쪽지 요청 문장처럼 여러 줄을 쓰는 곳은 `textarea.input`. 색·모서리·포커스·오류는 위와 같고, 높이만 최소 96px(버튼 높이 2배)·행간 1.5·**세로로만** 늘릴 수 있다(가로로 늘리면 390px 폭을 넘는다). 글자 16px. 화면마다 inline 스타일로 높이를 따로 주지 않는다.

### 5-10. 바텀시트·대화상자·토스트

- **바텀시트:** 동의·선택·필터에 사용. 상단 20px 모서리, 손잡이 막대, 하단에 Primary + Text 버튼. 시트 뒤 화면은 어두운 막 `--color-scrim`(11절)으로 덮고, 막을 누르면 시트가 닫힌다.
  - 예: 해봤노트 공개 동의, 쪽지 요청 확인, 신고 사유 선택.
- **확인 대화상자:** 되돌릴 수 없는 동작(차단, 삭제)에만.
- **토스트:** 하단 탭 위 16px, CHARCOAL 배경 + 흰 글자, 3초 표시. 예: "질문함에 담았어요".

### 5-11. 아이콘

- **Lucide** 아이콘 세트(선형)로 통일. 선 굵기 **1.75px**, 끝 둥글게.
- 크기: 탭·헤더 24px, 본문 안 20px, 태그 안 12~14px.
- 색: 기본 NAVY 또는 TEXT MUTED. 분야·상태 아이콘만 해당 fg 색.
- 채운 아이콘, 3D, 이모지 아이콘은 쓰지 않는다.

## 6. 상태 패턴 (모든 화면 공통)

### 6-1. 근거/출처 블록 ⭐

기획서의 핵심 차별점("이수 기록으로 확인된 경험자의 답, 근거 표시")을 보여주는 공통 블록. **해봤노트 상세의 노트 틀 각 항목 아래**와 **인터BOO 물어보기 답변 아래**에 둔다.

```
┌ ✦ 근거 4건 · 보고서 2 · 선배 인터뷰 2 · 최근 2025-2학기       [펼치기 ▾] ┐
│  · 선배 인터뷰 | 2025                                                           │
│  · 보고서      | 2024                                                           │
└──────────────────────────────────────────────────────────────┘
```
- 배경 SOFT MINT, 아이콘·숫자 HUFS GREEN, 설명 CHARCOAL 14px.
- 출처 이름은 1-2절 「출처 종류」: 「보고서」(현장실습 노트는 「현장실습후기」) · 「선배 인터뷰」.
- **요약 문단이 있는 칸(8-1, 11/25)**: 근거는 **요약 문장마다 끝에 붙는 출처**(「보고서 2025 · 선배 인터뷰 2026」)다. 원문 문장을 따로 펼쳐 보이지 않고(「원문 N건 보기」 없음), 틀린 내용 신고도 요약 문장에 한다(8-1). 칸 아래 근거 블록의 수치는 그대로 칸의 모든 문장 기준. **(11/26, #321)** 요약은 개조식(8-1 ②)이고 문장마다 출처 연도 옆에 중립 칩 「선배 N명」(그 문장 `sources`의 서로 다른 문서 수, 11/26 #324)을 둔다. 비용 칸 분포 띠(8-1 ②-1)도 코드 집계라 **SOFT MINT·HUFS GREEN을 쓰지 않는다**(AI가 만든 것 아님).
- 출처 한 줄: 출처 종류 + **연도**(v4.3: `2024`처럼 학기 없이). 이름·학번·학과·입학년도는 넣지 않는다 — 노트가 프로그램 단위라 학과+연도만 보여도 소수 학과에서 사람이 특정될 수 있어 학과도 빼고, 머리줄의 「최근 2025-2학기」는 프로그램 집계값이라 학기까지 둔다.
- **근거 적음 라벨**(v4.3): 칸의 근거가 1~2건이면 머리줄 오른쪽에 중립 라벨 「선배 1명의 경험이에요」(1건·2건 모두 이 고정 문구 — 11/26 #295. 문장 수는 선배 수가 아니고 서버에 사람 수 필드가 없다, spec getNote). 보류하지 않는다.
- **오래된 근거**(v4.3): 칸의 근거가 모두 2년 넘은 연도이면 블록 아래 정보 라벨 「최근 경험이 없어요」 + Outline 「질문함에 담기」.
- **자동 분류 라벨**(v4.3): 현장실습 노트에서 `autoClassified: true` 문장은 출처 한 줄 끝에 작은 중립 라벨 「자동 분류」. 신고 버튼은 그대로.
- 학교 규정과 관련된 내용은 블록 아래에 **정보 라벨** "공식 안내 보기 ›"를 붙여 공식 안내로 연결한다. **(11/27, #357·#331-1)** 서버가 `officialPhone`을 주면 그 옆에 전화 링크(phone 16px + 「02-2173-9999」, `tel:`). 메일은 응답에 없어 보이지 않는다.
- **「꼭 확인」 안내(11/27, #357)**: 물어보기 ok·hold 답에 `officialCheck`가 오면 근거 블록 아래 정보색 상자(SOFT BLUE, 12px 모서리) — 정보 라벨 「꼭 확인」 + 문구(14px) + 「공식 안내 보기 ›」·전화. 코드 고정 문구라 근거 블록과 섞지 않고 AI 색(GREEN·MINT)을 쓰지 않는다.
- **질문함 안내(11/27, #331-1)**: 물어보기 hold·official 답이 질문함에 담기면(`questionId`) 맨 아래 14px TEXT MUTED 한 줄(info 16px) 「질문함은 선배 인터뷰 때 묻는 질문이에요. 부서가 답하는 창구는 아니에요.」

### 6-2. 근거 없음 (0건)

- **틀은 그대로 두고 값만 비운다.**
```
┌ ✦ 근거 0건 · 보고서 – · 선배 인터뷰 – · 최근 –                                ┐
│  아직 이 항목을 경험한 선배의 이야기가 없어요.                                │
│  [질문함에 담기]  (외곽선 버튼)                                                │
└──────────────────────────────────────────────────────────────┘
```
- 배경은 SOFT MINT 대신 **NEUTRAL BG**, 숫자는 TEXT MUTED. "0건"은 숫자로, 나머지 값은 "–"로 표시한다.
- 인터BOO 물어보기에서 근거가 없으면 답을 지어내지 않는다. 위 블록 + "질문함에 담았어요" 토스트 + **닮은선배 보기**(보조 버튼)를 보여준다.

### 6-3. 로딩

- 목록·카드: **스켈레톤**(NEUTRAL BG 블록, 은은한 깜빡임). 스피너는 버튼 안 짧은 처리에만.
- AI 생성 중: 상태 라벨 「✦ 정리하는 중…」(SOFT MINT + HUFS GREEN). 생성 중인 영역에만 스켈레톤.

### 6-4. 빈 화면

- 구성: BOO 80px(또는 Lucide 아이콘 48px TEXT MUTED) → 18px 제목 1줄 → 14px 설명 1줄 → 버튼 1개.
- 예: 스크랩 없음 → "아직 담아둔 해봤노트가 없어요" / [해봤노트 둘러보기].

### 6-5. 오류

- 화면 안 오류: 오류 상태 라벨 + 문구 + [다시 시도](외곽선). 화면 전체를 빨갛게 칠하지 않는다.
- 네트워크 오류는 토스트로 짧게 알린다.

### 6-6. 잠김(조건 미충족)

- 기획서: "들려주기 또는 물어보기 초기 미션 완료 후에 선배 추천 버튼 활성화".
- 비활성 버튼 + 잠금 아이콘 + 조건 문구 14px. 숨기지 않고 보여 준다.

## 7. 대표 화면 6종 규칙

### ① 인터BOO

- 상단: 제목 「인터BOO」 + 설명 1줄 + BOO 안내 일러스트(오른쪽).
- 바로 아래 **들려주기 / 물어보기** 세그먼트(트랙 NEUTRAL BG, 선택된 쪽은 흰 알약 + NAVY 글자 + 그림자).
- **들려주기**: 노트 틀 진행 칩(5-7) → 채팅. **BOO는 질문함에 있는 후배 질문(최대 3개)을 먼저 묻고**(v4.3 — 11/25 v2: 칸이 아니라 질문이 속한 칸으로 묻는다, 5-7), 그 다음 근거가 적은 항목부터 묻는다. 첫 화면 안내 「후배 1명이 이 경험을 기다리고 있어요」(pendingQuestions가 1 이상일 때, 정보 라벨).
- **AI 요약 바 (들려주기 모드에만 표시)** — 입력창 바로 위에 고정:
  ```
  ┌ ✦ 내 이야기 3칸 · 보고서 2칸              [ ✦ AI 요약 ] ┐
  └──────────────────────────────────────────┘
  ```
  - 바: 높이 44px, SOFT MINT 배경, 12px 모서리, 좌우 여백 12px. 왼쪽 문구 HUFS GREEN 14px 600.
  - 왼쪽 문구(spec [v2] 진행률): 「내 이야기 N칸 · 보고서 M칸」 — N = 내가 답한 칸, M = 내가 답하지 않았지만 보고서가 이미 채운 칸(진행 칩의 「보고서」 표시와 같음).
  - 버튼 「AI 요약」: 높이 32px 알약형, NAVY 배경 + 흰 글자 14px 600, ✦(sparkles) 아이콘.
  - 활성 조건: 노트 틀이 **1개 이상 채워졌을 때**. 0개이면 비활성(6-6) + 문구 「한 항목 이상 이야기하면 요약할 수 있어요」.
  - 누르면 **AI 요약 미리보기(2단계)** 로 이동한다. 대화를 끝내지 않아도 언제든 누를 수 있다.
  - 물어보기 모드에서는 표시하지 않는다(물어보기는 노트를 만들지 않음).
- **물어보기**: 채팅. BOO 답변 아래 **근거/출처 블록(6-1)** 과 관련 해봤노트 카드 링크. 근거가 없으면 6-2.
- 설명 문구 예: 들려주기 "BOO에게 경험을 들려주면 노트로 정리해 드려요." / 물어보기 "선배들의 해봤노트를 근거로 답해 드려요."

### ② AI 요약 미리보기 (들려주기 결과, 2단계)

- 진입: 인터BOO의 **AI 요약 바 → 「AI 요약」**. 상세 헤더(← AI 요약 미리보기), **하단 탭 숨김**.
- 흐름(기획서: 대화 주제화·요약 → 내 경험노트 → 본인 동의 시 해봤노트 작성). **저장은 기본, 공유는 선택** (v4.1):
  ```
  인터BOO 대화 → [AI 요약] → 요약 완료 = 내 경험노트에 자동 저장(나만 보기)
                                   ├→ [해봤노트에 공유] → 공개 동의 시트(문장별 켜기/끄기) → 해봤노트 반영
                                   └→ [나중에 할게요] → 내 보관함 · 내 경험노트 탭 (언제든 상세에서 공유 가능)
  ```
  - 사용자가 '저장'과 '공유' 중 하나를 고르는 구조가 아니다. 요약이 끝나면 항상 내 경험노트에 남고, 공유는 그 위에 더하는 행동이다.
- 상단: BOO 안내(80px) + 상태 라벨 「✦ 대화 정리하는 중…」 → 완료 시 「✓ 요약 완료 · 내 경험노트에 저장됨」(긍정 라벨, lock 아이콘 없이 check).
- 요약 카드: 머리 띠 SOFT MINT + HUFS GREEN 아이콘 + 「(프로그램명) 경험노트 (요약 초안)」, 본문 흰색. 이 카드는 **내 경험노트 원본**이며, 해봤노트에는 공개 동의한 문장만 들어간다.
- 본문 항목은 **노트 틀 순서(교환·파견: 지원·학점·비용·생활·팁·배운점)** 로 정리. 아직 이야기하지 않은 항목은 "–"로 둔다(6-2와 같은 원칙). 인턴·비교과는 각자의 노트 틀(1-2절) 순서. **후배 질문에 답한 문장**(`asked`가 있는 문장)은 어느 칸이든 앞에 작은 인용 「Q. 후배 질문 원문」 + A(내 답)로 보인다(11/25 v2 — 공개 동의 시트도 같음).
- 이 화면에는 해봤노트 관련 블록을 두지 않는다(v4.1). 화면 = 내 경험노트, 해봤노트 = 공유했을 때의 결과이므로 결과는 공개 동의 시트에서 보여 준다. 요약 카드가 그만큼 화면을 넓게 쓴다.
- 하단 고정 버튼:
  - Primary 「해봤노트에 공유」 → **공개 동의 바텀시트**(아래).
  - Secondary 「나중에 할게요」 → 내 보관함 · 내 경험노트 탭으로 이동 + 토스트 「내 경험노트에 저장돼 있어요. 언제든 공유할 수 있어요」.
  - Text 「대화 이어가기」 → 인터BOO로 돌아감(같은 경험노트에 이어서 채움).
- **공개 동의 바텀시트** (문장 단위 동의, v4.1), 위에서 아래 순서:
  - **① 「반영될 해봤노트」 블록** (시트 맨 위): 내 이야기가 어느 해봤노트에 합쳐지는지 보여 준다.

### ④ 닮은선배

- 상단: 제목 + 설명("내가 궁금한 경험을 해본 선배 중, 출발점이 비슷한 선배를 추천해요.") + 추천 기준 한 줄("학과 → 이중전공 → 단과대 → 함께 들은 비교과 순으로 겹칠수록 앞에 보여 줘요.", 같은 `.sub`, 11/26 작업 42 안 A) + **추천 후보 고지**(11/26 작업 23 ① (다) — 경험한 선배는 따로 하지 않아도 추천 후보가 되므로 늘 보이게): 같은 `.sub` 「나도 해 본 경험이 있으면 비슷한 후배에게 닮은선배로 추천될 수 있어요.」 + `.link-more` 「추천받기 설정 ›」(→ 내 보관함 맨 위 「닮은선배로 추천받기」 스위치, 7-⑥) + BOO. 추천 기준에 점수 숫자·매칭률 %·「AI가 골라요」를 쓰지 않는다(추천은 규칙, `functions/score.py`).
- 「나의 프로필 요약」 카드(11/27 개편): SOFT BLUE 배경, 안쪽 여백 16px, 행 간격 12px. 위에서부터 네 줄:
  1. 「나의 프로필 요약」(12px 600 TEXT MUTED)
  2. 학과·학년·이중전공
  3. **「관심 경험:」**(14px TEXT MUTED) + 분야 키워드 칩(5-6) **[국제교류][현장실습][비교과]** — 늘 세 개, 하나만 고른다(선택 NAVY). 처음 들어오면 아무것도 고르지 않은 상태. 390px에서 한 줄(칩 좌우 여백 12px). 고른 활동 설명 글(「교환학생·독일·…」)은 두지 않는다.
  4. **세부 활동 칩 줄**(분야를 골랐을 때만): 내가 확인한 활동을 키워드 칩으로 **가로 한 줄**(줄바꿈 없음, 칩 너비 = 이름 길이, 최대 220px 말줄임 + `title`·`aria-label`에 전체 이름, 칩 사이 8px). 넘치면 **이 줄 안에서만** 가로 스크롤(카드·화면 폭은 그대로). 모바일은 손가락 스와이프만(화살표 없음), **PC(마우스)**는 줄 양 끝에 `chevron-left`/`chevron-right` 44px 아이콘 버튼 — 칩 목록 밖에 있어 칩을 가리지 않고, 맨 앞·맨 끝이면 그쪽 비활성, 칩이 다 보이면 숨김. **스크롤·화살표는 보이는 위치만 바꾸고 칩을 눌러야 활동이 바뀐다**(스와이프하다 뗀 것은 누름이 아님). 활동은 하나만 고른다. 분야를 고르는 것만으로 활동이 골라지지 않는다.
  - 세부 활동 = 해봤노트에서 연 노트 · 검색 결과에서 연 노트 · 질문함 질문의 노트 · 스크랩을 **노트 id로 합친 것**(중복 없음, 최근 순 — 시각이 없는 스크랩은 뒤). 검색어만 친 것은 칩이 아니다. 그 분야 활동이 없으면 14px 「아직 확인한 활동이 없어요.」 + `.link-more` 「해봤노트 둘러보기 ›」, 목록을 못 받았으면 오류 라벨 「활동 목록을 불러오지 못했어요」 + 「다시 시도」.
  - 해봤노트·질문함의 「닮은선배 보기」(`?noteId=`)로 들어오면 그 분야와 활동을 골라 둔 채 연다.
- **추천 목록은 활동을 골랐을 때만** 보인다(분야만 고른 상태·아무것도 안 고른 상태에서는 제목·카드 없음). 분야를 바꾸면 고른 활동과 목록을 비우고 활동 줄은 맨 앞부터. 추천 후보는 **고른 활동을 실제로 경험한 선배만**(서버 `recommendSeniors` — 같은 분야의 다른 활동·비슷한 활동 경험자는 넣지 않는다, 유사 활동 확장은 로드맵). 순서는 위 추천 기준 그대로. 경험자가 없으면 6-4 「아직 해당 활동을 경험한 선배가 없어요」. 잠김(6-6)이면 고른 것과 상관없이 잠김 안내.
- 추천 목록 제목: 「추천 선배 N명」 — **N은 실제 표시 카드 수와 같아야 한다.**

  - 화면에 들어오면 서버가 준 상위 **3명**이 바로 보인다. 첫 추천을 버튼 뒤에 숨기지 않는다.

  - 중립 아바타(원형 40px, NEUTRAL BG + TEXT MUTED 사람 아이콘). 인물 사진·인물 일러스트는 쓰지 않는다.

  - 경험 태그(분야 태그 + 활동명) 줄은 **카드에 두지 않는다**(11/27 — 위 프로필 요약에서 고른 활동이 이미 보임). 선배 프로필(2단계)의 「경험」 카드에는 그대로 둔다(분야색 3-3).
  - 추천 이유 1줄: SOFT MINT 아이콘 + HUFS GREEN ✦ + CHARCOAL 14px (AI가 쓴 문장임을 표시).

  - **분야 띠(11/27, #372 작업 118)**: 카드·상세 위에 분야 띠(분야 태그 + 프로그램 이름). 프로그램이 없으면 중립 띠 「프로그램을 정하지 않았어요」. 프로그램 없는 대기 질문은 「아직 선배에게 전달되지 않았어요. 프로그램을 고르면 전달돼요」 + Primary 「궁금한 것 정리하기」.

- **스크랩 탭**: 해봤노트 카드(7-③과 같은 컴포넌트), 스크랩 아이콘은 채운 상태.

## 8. 세부 화면 확장 규칙 (향후 구현 시 동일 적용)

> 아래 화면은 기획서에 기능이 있으나 대표 화면(7절)에는 없는 화면이다. 모두 2단계 이상이므로 **상세 헤더 + 하단 탭 숨김**(5-2)을 따른다. 새 컴포넌트를 만들지 말고 5·6절 컴포넌트를 조합한다.

| 세부 화면 | 사용 패턴 | 색·자산 |
|---|---|---|
| 선배 프로필 | 상세 헤더 → 중립 아바타 + 「학과 + 선배 + 영문 대문자」 → 경험 태그(분야색) → 추천 이유 → 하단 고정 Primary 「쪽지 요청」 | 분야색 + MINT |
| 해봤노트 상세 | 상세 헤더 → 커버(분야 띠 + 5항목) → 노트 틀 탭(지원·학점·비용·생활·팁·배운점 — 11/25 v2, 「후배 질문」 탭 없음) → 항목별 문장 + 근거/출처 블록(6-1/6-2). **배운점 칸은 여러 선배 문장을 합쳐 요약하지 않고 선배별 원문 인용**(문장 + 「선배 A · 2025」)으로 보여 준다(11/22, PRD 9-1). **학과는 넣지 않는다** — 노트가 프로그램 단위라 소수 학과면 사람이 특정된다. 글자(A·B…)는 서버가 `getNote`에 넣는 **노트 안에서만 쓰는 글자**라 닮은선배 화면의 글자와 다르다. 글자는 `getNote` 배운점 문장의 `senior`이고, 값이 없는 문장은 출처 칩 「선배 인터뷰 · 2025」만 보여 준다. **후배 질문에 답한 문장(11/25 v2)**: 질문이 속한 칸에 일반 문장으로 들어가고, 출처 줄에 중립 라벨 「후배 질문에 답한 문장」(message-circle)만 붙는다. 해봤노트에는 Q(후배 질문 원문)를 보이지 않는다 — Q·A 쌍은 질문한 후배의 질문 상세에서만. 본문 문장은 사전 생성 노트의 **원문 인용**이고, 서버가 칸 `summary`를 주면 그 칸은 **칸별 요약 문단**(8-1, 11/25)으로 보여 준다 → "이 노트 경험자 중 닮은선배" 카드 | 분야색 + MINT(근거) |
| 인터BOO 물어보기 답변 | 채팅 + 근거 블록 + 관련 노트 카드 링크 + 근거 없음 처리 | SOFT BLUE / MINT |
| 내 경험노트 상세 | 본인만 열람 표시(🔒 + "나만 보기" 정보 라벨), 노트 틀 요약(공유한 문장에는 작은 긍정 라벨 「공유됨」), 「자소서용 요약 보기」 Secondary(**v4.3: 이번 범위에서는 비활성(6-6) + 문구 「운영 연계 시 열려요」**), 「해봤노트에 공유」 Primary(이미 공유했으면 「공유 범위 바꾸기」). **문장 고치기(11/23)**: 문장마다 Text 「문장 고치기」 → 7-② 공개 동의 시트와 같은 모양(여러 줄 입력창 + Secondary 「저장」 / Text 「취소」), 라벨 「내 경험노트 문장」, 안내 「나만 보는 문장이에요. 해봤노트 문장은 바뀌지 않아요.」. 나만 보는 노트라 공개 문장 검사는 없다. 고친 문장에는 중립 라벨 「내가 고친 문장」. 이미 공유한 노트면 저장 뒤 정보 라벨 「해봤노트 문장은 그대로예요 · 해봤노트 문장 고치기」(→ 공개 동의 시트 「공유 범위 바꾸기」) | MINT |

SVG는 `createElementNS`로 그리고 `aria-label`에 같은 문장을 넣는다. **코드 집계라 중립색만**(HUFS GREEN·SOFT MINT 금지). `stats`가 없거나 값이 맞지 않으면 상자를 그리지 않는다.
  - **②-2 소주제 묶음**(생활·지원 칸, `summary[].topic`이 하나라도 있을 때만): 소주제 라벨(14px 600 NAVY) 아래 그 문장들을 모은다. 생활 칸 순서는 1-2절 「주거 · 교통 · 음식 · 행정 · 사람」, 그 밖의 라벨은 처음 나온 순서. 소주제가 안 잡힌 문장은 라벨 없이 **맨 뒤**에 구분선(BORDER 1px) 아래로. `topic`이 하나도 없으면 묶지 않고 한 목록.
- **「개인 경험」 라벨**: 요약 문장이 학교 규정에 닿는 내용(`official`)이면 칸 문장과 같은 중립 라벨 「개인 경험」(user 아이콘)을 그 문장 출처 뒤에 붙인다. 공식 안내가 아니라 선배 경험임을 알리는 표시다.
- **③ 요약 문장 신고(11/25, #266)**: 「원문 N건 보기」 접기는 없앤다. 틀린 내용은 **요약 문장**을 길게 누르거나(0.5초, 모바일·PC) 문장 위에서 드래그해(PC) **문장 하나 전체**를 고른다(11/26 — 브라우저 글자 선택 대신. 요약 문장의 글자 선택·길게 누르기 메뉴를 끈다. 한 번에 한 문장만 — PC 드래그도 시작한 문장 하나). 고른 문장은 **오류색 글자 + 오류색 밑줄 2px**(여러 줄이어도 문장 전체, 선택 표시라 ②의 「밑줄 강조 금지」와 다르다). 문장 마지막 줄 끝 아래 8px에 풍선 두 개: Outline 「복사」(copy 아이콘 — 그 문장 전체를 복사, 토스트 「문장을 복사했어요」) + 「신고하기」(위험 버튼 색: 흰 바탕 + 오류색 글자·1px 테두리, flag 아이콘, 높이 44px 알약, 떠 있는 그림자). 「신고하기」 → 신고 시트(맨 위에 신고할 문장 인용 → 사유 하나 고르기, 필수) → `reportStatement(summary[].lineId, 사유)`. 응답이 오면 그 요약 문장만 바로 빼고 토스트 「신고했어요. 이 문장은 숨겼어요」, 요약 문장이 하나도 안 남으면 그 칸은 원문 목록으로 돌아간다. 시트를 취소하거나 다른 곳을 누르거나 Esc면 고른 표시를 풀고 원래 문장 모양으로. 문단 아래 안내 한 줄(Caption, TEXT MUTED, flag 14px) 「문장을 길게 누르거나 드래그하면 복사하거나 신고할 수 있어요」. 키보드: 요약 문장에 Tab으로 가서 Enter → 바로 신고 시트.
- **④ 새로 더해진 선배 이야기**: `newLines`가 1 이상이면 칸 `lines`의 끝 N개를 소제목 「새로 더해진 선배 이야기 N건」(14px 600 NAVY, 앞에 HUFS GREEN `message-circle-plus` 16px) 아래 원문 카드로 펼쳐 보여 준다. 요약은 다시 만들지 않으므로 이 문장은 문단에 섞지 않는다. `newLines`가 0이거나 없으면 이 줄은 없다.
- **요약이 없는 칸**(`summary` 없음): 지금처럼 원문 문장 목록. **배운점 칸은 늘 선배별 원문 인용**(8절 해봤노트 상세)이고 요약 문단을 만들지 않는다.
- 신고로 문장을 숨기면 그 문장을 출처로 쓴 요약 문장도 함께 빠진다. 남은 요약 문장이 없으면 그 칸은 원문 목록으로 돌아간다.

## 9. 데이터·콘텐츠 표기

- 대회 기간 화면에는 **가상 데이터만** 쓴다(`외대人사이드_가상학생_1000명.xlsx`). 실제 명단·원문을 쓰지 않는다.
- 학생·선배 이름과 학번(입학년도 포함)을 화면에 쓰지 않는다. 표시는 "학과 + 선배/후배 + 영문 대문자"(예: 독일어과 선배 A).
- 학과명은 가상학생 파일의 학과(전공) 표기를 그대로 쓴다(예: 독일어과, 스칸디나비아어과, 프랑스어학부 FATI전공).
- 국가·대학명은 가상학생 파일의 파견국가·파견대학 값을 쓴다.
- 수치(질문 수, 만족도 등)는 서로 맞아야 한다. 예: "추천 선배 3명"이면 카드 3개.
- 화면 문구에 오탈자가 없어야 한다. 배포 전 1-2절 용어 표준과 대조한다.

## 10. 시안 이미지 생성 규칙 (배너·목업)

### 10-1. 원칙

1. **색은 3절 닫힌 팔레트의 HEX만** 쓴다. 이미지 생성 프롬프트에 HEX를 직접 적고 "이 외의 색 사용 금지"를 명시한다.
2. **BOO와 HUFS 심벌은 생성하지 않는다.** 원본 파일을 합성(붙여넣기)한다. 생성 도구가 합성을 지원하지 않으면 그 자리를 빈 흰 원으로 두고 편집 단계에서 원본을 넣는다.
3. 사진·인물 일러스트를 생성하지 않는다(7-③, 7-④ 규칙과 동일).
4. 모든 한글 문구는 **이 문서의 문구를 그대로 복사**해 넣는다. 생성 결과의 글자는 반드시 검수한다.
5. 가능하면 **HTML 목업 → 스크린샷** 방식으로 만든다. 색·글자·자산을 정확히 지킬 수 있다.

### 10-2. 프롬프트 템플릿


**관리 메모 (v4.1, 2026-11-16):** ① 교환·파견 노트 틀에 '배운점' 칸 추가(6칸, 인터뷰로만 채움, 해봤노트에서는 선배별 원문 인용). ② 들려주기 결과는 **저장은 기본, 공유는 선택**: 요약 완료 시 내 경험노트 자동 저장, 버튼은 「해봤노트에 공유」/「나중에 할게요」. ③ 공개 동의를 문장 단위로(본인 식별 문장 기본 꺼짐). ④ 헤더 막대차트 버튼은 직원 계정에서만, 목적지는 PC 관리자 콘솔(PRD v1). ⑤ 시안 이미지에서 주소줄 삭제(배너 v4). ⑥ 「반영될 해봤노트」 블록을 AI 요약 미리보기 화면에서 공개 동의 시트 맨 위로 이동, 요약 카드 제목은 '경험노트 (요약 초안)'로 확정. 배너 v5에서 ①칩 6개·2/6, ②카드 제목 '경험노트'·저장됨 라벨·배운점 행·나만 보기 라벨·「나중에 할게요」 반영, 반영될 박스 제거, 부서 리포트 화면 삭제(5개 화면). ⑦ 선배 표시명에서 학번 제거: 「학과 + 선배 + 영문 대문자」(배너 v5 ④ 반영). ⑧ 쪽지 보낸 사람은 「형용사 + 동물」 익명 닉네임(쪽지 요청 순간 생성, 대화마다 새로), 선배 쪽 받은 요청 카드에 학과 비표시. 이름 체계는 역할별로 하나씩(1-2절 '사람 이름').

**관리 메모 (v4.0, 2026-11-13):** 5-1절 리포트 아이콘 활성 문장 삭제. 5-2절에 화면 깊이 규칙(1단계만 하단 탭, 2단계 이상은 상세 헤더 + 탭 숨김) 추가. 인터BOO AI 요약 바와 AI 요약 미리보기 → 해봤노트 반영 흐름(공개 동의, 반영될 해봤노트, 반영 상태) 추가. 7-⑥ 내 보관함을 대표 화면으로 추가.
