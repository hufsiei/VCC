## 2. 시스템 구성도 ⬜
- 그릴 것: 화면(GitHub Pages, `screens/`) → `common/data.js`(`?server=all`이면 서버, 기본은 mock — 39에서 전환) → **API Gateway → NCP Cloud Functions**(`functions/`) → **Object Storage**(쪽지·질문함 등 `runtime/*.json`) + 사전 생성 데이터(`data/*.json`) → `callAI`(마스킹·사용자별 한도·기록) → HCX / Claude(PROVIDER).
- askBoo 흐름(**A안**, 11/26 결정 · `VCC_ASK_FULL=1` · 11/29 88로 확정): 규정 질문이면 공식 안내(정규식 먼저) → **① 질문 정리**(Sonnet: 앞 대화·제외·의도) → ② 의도별 갈래(대화=고정 문구 / 탐색=노트 카드 / 규정 / 경험) → ③ 프로그램 찾기 + **근거 전문**(코드, 문단째·최대 2만 자) → **④ 답 쓰기**(Sonnet, 전문을 읽고 문장마다 근거 번호 `[문단-문장]`, 근거 전문은 프롬프트 캐시 5분) → **⑤ 검증**(코드: 번호 없는 문장·근거에 없는 숫자·이름 버림 → Opus 원문 대조) → 다 버려지면 원문 인용(폴백 줄 말투는 HCX), 근거가 없으면 보류+질문함. 옛 길(③ 근거 추출 → ④ HCX 고르기 최대 8 → 답 쓰기)은 88 비교용으로 남고, A안이 되돌릴 조건(근거 없는 답 0건 못 지킴 또는 정답률 < 옛 길)에 걸리면 이 줄을 옛 길로 되돌린다(HCX 원칙 v3 9절). 그림은 미리 `docs/캡처/261126_miri_ai_diagram.png`(#373).
