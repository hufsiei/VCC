# HCX 대응 원칙 v3 (2026-11-23 개정)

BOO IT · 외대人사이드 · 원본 2026-11-14(토) 강미리 · v2 2026-11-16 · **v3 2026-11-23(월, 팀 합의)**
다른 PC나 새 AI 대화에서 작업을 이어갈 때 이 문서를 먼저 읽는다. v2는 `docs/HCX-원칙-v2.md`에 남기고, 8절 측정 기록은 거기서 본다.
근거: `docs/askBoo-v2 반영 검토안 (2026-11-23, 상의용).md` 2장, 봉인 1차(#150), 원우 #151, #156 측정.

## 1. 한 줄 결론 [v3 수정]

**코드가 할 수 있는 일은 코드가 하고, AI는 고르기(HCX)·쓰기(Sonnet)·검사(Opus)로 역할을 나누며, 근거 번호 없는 문장과 근거에 없는 숫자·이름은 코드가 버린다.**

v2의 "AI에게는 정답이 있는 작은 일만"은 한 걸음 바뀐다. AI가 답을 **쓰되**, 쓴 문장마다 어느 근거에서 왔는지 번호를 내게 하고, 번호가 없거나 번호의 원문에 없는 내용이 있으면 코드가 그 문장을 버린다. 다 버려지면 v2 방식(고른 문장 원문 인용)으로 폴백한다. 그래서 v2의 답이 최악의 경우가 되고, 더 나빠질 길은 없다. 모델은 호출별 PROVIDER(`hcx | sonnet | opus`)로 관리하고, CLOVA는 askBoo 변환(폴백)·충분판정·꼬리질문·쪽지검사에 남긴다(기획서·네이버클라우드상·네이버 심사위원). **[11/26]** askBoo 고르기는 플래그(`VCC_ASK_FULL`) 뒤에 둔다 — 켜면 고르기 없이 프로그램 근거 전문을 답쓰기에 넘기고(A안, `docs/prompts/askBoo-답쓰기-전문.txt`), 끄면 지금 길 그대로. 11/29 측정으로 확정(근거: 11/18 FDE Q&A 08:08 「서버가 NCP면 AI는 다른 모델 OK」, PRD 91·518행).

## 2. v2에서 v3로 바꾼 이유 (11/23 관찰)

- **실사용 캡처 6건(미리, 서버 연결)**: 「무역 관련 인턴 어떤가요?」에 KOTRA 후기 문장 3개가 그대로 나왔다(「덧붙이자면 …」). 「코트라 말고」「그 말이 아니라 추천해 주세요」에도 또 KOTRA. 「아까도 한 얘기잖아」「데이터가 없나요?」는 보류 + 질문함 저장. 「독일에서 인턴 어디 있어요?」는 빈 말풍선 + `null`(화면이 `notes` 상태를 몰랐음).
  - 원인은 네 가지다. **A 답이 아니라 발췌**(변환 단계가 끝맺음만 바꿈) · **B 대화 기억 없음** · **C 의도 구분 없음**(탐색·추천을 문장 검색으로) · **D 대화를 질문으로 취급**. "AI가 보고서를 이해 못 한다"는 A 하나다.
- **봉인 1차(#150, 11/23 15:12, 원우)**: 근거 없는 답 0건, 범위밖·함정 보류 10/10은 통과. 정답률 HCX 23/30·Sonnet 22/30이고 **틀린 7개는 두 모델이 똑같이 틀렸으며 모두 AI를 부르기 전 코드 단계의 보류**(규정 질문 못 알아봄 3 · 보고서 칸에 없는 주제 3 · 프로그램 못 찾음 1). 병목은 모델이 아니라 정규식 문지기였다.
- **원우 #151**(봉인을 보지 않고 새 확인용 질문으로): 규정 판별 2/12 → 11/12, 주제어 12/20 → 14/20. "낱말 목록으로는 안전하게 조금만 나아진다 — 놓치는 말이 끝없이 나온다." → 구조 변경 제안.
- **#156**(미리, v1 안 선반영): 규정 판별 넓힘(자격증·과제 마감 제외, 경험 말투 예외) + 주제어가 없어도 겹치는 근거를 고르기 AI에 넘김. topic_probe 112개: 답변 14 → 24, 보고서에 없는 주제 보류 24/24 유지, 개발 70은 70/70 그대로.

결론: 가드레일(프로그램 범위 안 근거 추출·사후 검증·동의 문장만 공개·보류→질문함→인터뷰)은 그대로 두고, **고르기 위에 "답 쓰기"를 얹고 앞에 "질문 정리"를 둔다.**

## 5. 설정·프롬프트 규칙 [v3 추가분 굵게]

- 사실을 다루는 호출은 Temperature 0, Thinking 끔(HCX), Max tokens를 출력 크기에 딱 맞게. Claude는 effort로만 깊이 조절.
- 출력은 항상 JSON. 코드는 첫 번째 `{...}`만 파싱하고 나머지는 버린다. 형식이 틀리면 AI 답을 버리고 기본 문구·폴백.
- 한 번에 한 가지 일만 시킨다. **질문 정리와 답 쓰기는 다른 호출**이다("정리하고 + 답하고"를 한 호출에 넣지 않는다).
- AI에는 고른 근거만 넣는다. 전체 근거를 넣으면 섞어서 지어낸다. **답 쓰기에 넣는 근거는 ④가 고른 최대 8개**이고, 근거마다 번호·프로그램·연도·"선배 N명"을 붙인다.
- **답 쓰기 출력은 문장마다 근거 번호를 받는다. 번호가 없거나, 번호의 원문에 없는 숫자·영문·고유명사·수량이 있거나, Opus 일치검사가 거짓이면 그 문장을 버린다. 다 버려지면 ④ 문장 원문 인용으로 폴백한다.** 「새 낱말」 규칙은 답 쓰기에는 쓰지 않는다(바꿔 쓰기를 허용하고 일치검사가 대신 본다). 측정에서 근거 밖 문장이 1건이라도 나오면 「새 낱말」 규칙을 다시 켠다.
- **대화 맥락은 화면이 `history`(최근 4턴: 사용자 말·그때 status·프로그램명)로 보내고 서버는 기억하지 않는다.** BOO의 답 원문은 history에 넣지 않는다(마스킹·토큰). `history`도 0장 마스킹을 거친다.
- **의도가 `대화`면 AI가 문구를 쓰지 않는다.** 코드의 고정 문구 + 칩이며 질문함에 저장하지 않는다.
- **"선배 1명의 경험이에요"는 AI가 쓰지 않고 코드가 `singleSenior` 라벨로 붙인다**(AI가 인원을 세게 하면 틀린다).
- 규정 판별은 정규식이 먼저다(보수 규칙). 질문 정리가 `의도: 규정`을 내도 정규식에 안 걸리면 경험질문으로 처리하지 않고 `official`로 보낸다(둘 중 하나라도 규정이면 규정).
- 테스트할 때는 매번 대화 초기화. **측정은 개발 70 + 다중 턴·탐색·대화 20 = 90개**, 기대답은 원우가 확정·서명. 규칙·프롬프트를 고칠 때마다 전부 재실행하고, 확인용 질문은 고치지 않고 한 번만 잰다(#151 원칙).
- 규정성 진술은 "개인 경험" 표시 + 공식 안내 링크. 모든 AI 호출은 `callAI(작업명, 입력)` 한 관문, 작업명→모델은 `PROVIDER` 표 한 곳, 키는 서버 환경변수에만, 입구에서 마스킹 + 사용자별 한도.

## 6. 대비책

- **폴백이 곧 v2다.** 답 쓰기·질문 정리·일치검사 중 어느 호출이 실패해도 v2 경로(정규식 대조 → 고르기 → 원문 인용)로 떨어진다. 시연이 깨질 길은 없다.
