## 3. 키·비밀이 있는 곳

값은 두 곳에만 있습니다. **로컬은 저장소 맨 위 `.env`(커밋 금지), 클라우드는 NCP 콘솔의 액션 기본 파라미터.** 이름은 [.env.example](../.env.example)과 같습니다.

| 이름 | 무엇 | 읽는 코드 |
|---|---|---|
| `CLOVA_KEY` | CLOVA Studio API 키(사람마다 따로) | `functions/ai.py` |
| `ANTHROPIC_API_KEY` | Claude API 키(사람마다 따로: `vcc-dev(ww)`·`vcc-dev(minji)`, 미리 것) | `functions/ai.py` |
| `VCC_LOGIN_PW` | 로그인 비번 표(JSON 한 줄). `"*"`는 가상학생 공용, 직원은 개별 항목 | `functions/account.py` |
| `ALLOW_ORIGIN` (선택) | CORS 허용 주소(쉼표 구분). 없거나 `*`만 있으면 Pages(`https://hufsiei.github.io`). `*`는 무시 | `functions/cloud/*.py` |
| `STORE_BACKEND` (선택) | `file`(기본) \| `ncp` | `functions/store.py` |

규칙(11/19·11/20·11/24): 키는 미리 계정에서 팀원별로 따로 발급합니다(Claude `vcc-dev(ww)`·`vcc-dev(minji)`, CLOVA도 사람마다). 자기 키를 다른 사람과 나누지 않고, 채팅·화면·커밋·캡처에 한 번이라도 보이면 즉시 폐기·재발급하고 단톡에 알립니다. 화면(브라우저)에는 키가 없습니다.

### 로컬 (미리 PC)
```
cd C:\dev\VCC
python functions/serve_screens.py          # 화면: http://localhost:8000/screens/login/ (이 PC만, .env·logs·runtime 안 열림)
cd functions
python local_fn.py                         # 서버 함수: http://localhost:8787
```
- 화면은 기본이 mock(`common/data.js`의 `USE_MOCK`)입니다. 함수별로 서버를 쓰는 방법은 README 「실행법」.
- 리허설 전 초기화: 서버를 끄고 `python functions/reset_runtime.py` → 다시 켭니다.

### 배포
- 화면: `main`에 병합하면 GitHub Pages가 자동 반영합니다(PR → 승인 1개 → 병합).
- 서버 함수(작업 58): `main` 받기 → `python -X utf8 functions/cloud/build.py` → 다운로드 폴더의 `vcc-functions.zip`을 NCP 콘솔 > Cloud Functions > 액션 `vcc/vcc-api`에 업로드. **서버 함수를 고친 PR이 병합될 때마다 다시 합니다**(화면과 달리 자동 반영 안 됨). build.py는 origin/main을 포함하지 않거나 zip에 키·`.env`·logs·runtime이 섞이면 멈춥니다.
  - 액션: 웹 액션, python:3.13, **HTTP 원문 사용(Raw) 켬**(꺼져 있으면 진입점이 거절), **헤더 옵션 설정 켬**(아래 CORS), 512MB·60초, VPC `vcc-vpc`/`vcc-private`(바깥은 NAT `vcc-nat-gw`로).
  - 기본 파라미터 이름: `CLAUDE_KEY` `CLOVA_KEY` `VCC_LOGIN_PW` `ALLOW_ORIGIN` `STORE_BACKEND=ncp` `NCP_OS_BUCKET` `NCP_OS_ACCESS_KEY` `NCP_OS_SECRET_KEY`. 값은 콘솔에만.
  - API Gateway: Product `vcc` / API `vcc-api` / 리소스 `/{fn}` POST·OPTIONS → 액션 / Stage `dev`. 경로 `{fn}`이 액션에 넘어가지 않아 `data.js`가 `?fn=<함수 이름>`을 붙입니다.
  - CORS(11/25): 헤더는 진입점 `_cors`가 모든 응답(OPTIONS·POST·오류)에 붙입니다. 허용 Origin이면 `Access-Control-Allow-Origin`에 그 값 1개, 다른 Origin이면 없음. `*`는 쓰지 않습니다(PRD 9장). 액션 「헤더 옵션 설정」(API `custom-options`)이 꺼져 있으면 웹 액션 플랫폼이 모든 응답에 `*` 기본 묶음(메서드 7개)을 붙이고 OPTIONS도 대신 답합니다 — 이 상태로 진입점이 붙이면 Allow-Origin이 두 줄이 되어 브라우저가 막습니다(11/24). API Gateway는 헤더를 그대로 넘깁니다(`x-ncp-apigw-response-origin: ENDPOINT`).
  - CORS 점검: `curl -s -o /dev/null -D - -X OPTIONS "<공개 주소>/getMe?fn=getMe" -H "Origin: https://hufsiei.github.io"`와 같은 주소에 `-X POST -d '{}'` → 둘 다 Allow-Origin 줄이 정확히 1개(`https://hufsiei.github.io`), Allow-Methods `POST, OPTIONS`. Origin을 `https://evil.example`로 바꾸면 Allow-Origin 줄이 없어야 합니다.
  - 점검: 기본 파라미터에 `VCC_DIAG=1`을 잠깐 넣고 `POST <공개 주소>/_diag?fn=_diag` → 경로·파라미터 **이름**과 Object Storage·CLOVA 접속 여부. 끝나면 `VCC_DIAG`를 지웁니다(없으면 _diag는 「없는 함수」로 거절).
  - 서버 오류: 화면에는 「서버 처리 중 문제가 생겼어요」만 갑니다. 원문(예외 종류·Object Storage 오류 등)은 액션 로그(NCP 콘솔의 액션 실행 로그)에 `[vcc] <함수> 오류 …`로 남습니다(키 값은 `***`).
  - 공개 주소 화면은 기본 mock입니다. 서버로 보내려면 주소 끝에 `?server=all`(그 탭만).
  - 서버의 AI 호출 기록은 액션 `/tmp`에 쌓였다가 재시작 때 사라집니다 → 서버 키 비용은 Claude 콘솔(키별)·NCP 이용 요금으로 봅니다.
  - 리허설 전 초기화: 공개 쪽 기록은 버킷 `vcc-runtime`의 `runtime/` 객체를 지웁니다(`python reset_runtime.py --ncp`, 키는 `.env`의 `NCP_OS_*`). 액션은 요청마다 새로 읽으니 재배포는 필요 없습니다.
- 코드 프리즈: 12/3(목) 밤. 그 뒤는 치명 오류 수정만.
