# 운영노트 — 외대人사이드 이관 문서 (작업 77)

> 초안 2026-11-21 (Claude 작성, 미리 검토 전). **「확인 필요」** 표시는 아직 정해지지 않았거나 미리가 채울 칸입니다.
> 이 저장소는 공개입니다. 이 문서에는 **키 값·비번·개인 메일 주소를 적지 않습니다.** 위치와 이름만 적습니다.

이 시스템은 정적 화면(GitHub Pages) + 서버 함수(지금은 미리 PC의 `local_fn.py`, 이사 후 NCP Cloud Functions) + 가상 데이터(`data/`)로 돌아갑니다. 학교 시스템(MY HUFS)에 올릴 때 바꿀 곳은 맨 아래 「이관 절차」에 모았습니다.

## 3. 키·비밀이 있는 곳

값은 두 곳에만 있습니다. **로컬은 저장소 맨 위 `.env`(커밋 금지), 클라우드는 NCP 콘솔의 액션 기본 파라미터.** 이름은 [.env.example](../.env.example)과 같습니다.

| 이름 | 무엇 | 읽는 코드 |
|---|---|---|
| `CLOVA_KEY` | CLOVA Studio API 키(사람마다 따로) | `functions/ai.py` |
| `ANTHROPIC_API_KEY` | Claude API 키(사람마다 따로: `vcc-dev(ww)`·`vcc-dev(minji)`, 미리 것) | `functions/ai.py` |
| `VCC_LOGIN_PW` | 로그인 비번 표(JSON 한 줄). `"*"`는 가상학생 공용, 직원은 개별 항목 | `functions/account.py` |
| `ALLOW_ORIGIN` (선택) | CORS 허용 주소(쉼표 구분). 없으면 Pages + localhost:8000 | `functions/cloud/*.py` |
| `STORE_BACKEND` (선택) | `file`(기본) \| `ncp` | `functions/store.py` |

규칙(11/19·11/20·11/24): 키는 미리 계정에서 팀원별로 따로 발급합니다(Claude `vcc-dev(ww)`·`vcc-dev(minji)`, CLOVA도 사람마다). 자기 키를 다른 사람과 나누지 않고, 채팅·화면·커밋·캡처에 한 번이라도 보이면 즉시 폐기·재발급하고 단톡에 알립니다. 화면(브라우저)에는 키가 없습니다.

## 4. 비용

| 항목 | 주체 | 금액 |
|---|---|---|
| NCP(Cloud Functions·NAT Gateway·Object Storage·CLOVA Studio) | 크레딧 수령 전까지 미리 부담(실비), 수령 후 대회 지원 크레딧 | 확인 필요(크레딧 수령 전). HCX 단가도 확인 전. NAT Gateway는 시간 과금이라 켜는 날 작업 47 ⑤까지 한 번에 끝낸다 |
| Claude API | 미리 부담(미리 계정, 키는 팀원별) | 팀 상한 = 미리 계정 선불 잔액. 질문 1건당 원가·연간 추정은 작업 55에서 채움 |
| GitHub Pages | 무료(공개 저장소) | 0 |

비용 안전장치: 사용자별 AI 호출 분당 10·일 100, 전역 일 2,000건(`functions/limits.py`). 개발 중에는(11/24)
- Claude: 키별 한도가 없다. 팀 전체 상한은 미리 계정의 **선불 잔액**이다(다 쓰면 호출이 멈춘다).
- NCP: **Budgets 알림**(50%·80%, 작업 72)으로 본다.
- 각자: `python -X utf8 functions/ai_usage.py` → `오늘 내 AI $x.xx (Claude n회) · HCX m회 k토큰`(이 PC 로그 `functions/logs/ai-calls.jsonl` × 단가 Sonnet 5.5 $2/$10·Opus 5.5 $4/$20 per 1M). 세션 시작 [VCC] 줄에 자동으로 뜨고, PR 올릴 때 마지막 답·작업일지 「오늘 AI」 줄에 적는다. HCX는 단가 확인 전이라 회수·토큰만(단가는 `ai_usage.py`의 `HCX_PRICE`에 채운다).
- 하루 정리(milend): 세 사람 일지의 「오늘 AI」 줄을 `ai_usage.py --journals`로 더하고, Claude 콘솔의 키별 비용·NCP 이용 요금과 대조한다.

## 5. 실행법

### 로컬 (미리 PC)
```
cd C:\dev\VCC
python functions/serve_screens.py          # 화면: http://localhost:8000/screens/login/ (이 PC만, .env·logs·runtime 안 열림)
cd functions
python local_fn.py                         # 서버 함수: http://localhost:8787
```
- 화면은 기본이 mock(`common/data.js`의 `USE_MOCK`)입니다. 함수별로 서버를 쓰는 방법은 README 「실행법」.
- 리허설 전 초기화: 서버를 끄고 `python functions/reset_runtime.py` → 다시 켭니다.

### 시험
```
cd functions
python test_account.py   # 그 밖에 test_*.py 전부 — 하나라도 틀리면 종료코드 1
python ../tools/check_week1.py           # 데이터 연결·별칭 대조·공개 주소 200 (--live: askBoo 실호출 1건)
python ../tools/build_notes.py --check   # 해봤노트 생성 점검(원우)
```

### 배포
- 화면: `main`에 병합하면 GitHub Pages가 자동 반영합니다(PR → 승인 1개 → 병합).
- 서버 함수: NCP 콘솔 > Cloud Functions > 액션에 붙여 넣고 웹 액션을 켭니다. 확인용 `functions/cloud/hello.py`·`clova_once.py`. `local_fn.py` 경로 전체 이사는 작업 58 ①(확인 필요: 크레딧 수령 후).
- 코드 프리즈: 12/3(목) 밤. 그 뒤는 치명 오류 수정만.

## 7. 이관 절차 — MY HUFS에 올릴 때 바꿀 곳

| 바꿀 곳 | 지금 | 운영에서 |
|---|---|---|
| `common/data.js` `FN_BASE` | `http://localhost:8787` | 학교 서버 함수 주소 |
| `common/data.js` `USE_MOCK` | `true` | `false` (mock 파일은 배포에서 빼도 됨) |
| 로그인 | `VCC_LOGIN_PW` 비번 표 + `functions/sessions.py` 토큰 24시간 | 학교 SSO 토큰(로드맵, 작업 55). `account.py`·`sessions.py`만 바꿈 |
| `functions/store.py` | 파일 저장 | `STORE_BACKEND` — Object Storage 또는 학교 DB. 다른 코드는 `store.load/save`만 씀 |
| `functions/ai.py` `PROVIDER` | 작업별 hcx·sonnet·opus | 학교가 계약한 모델로 이 표만 바꿈. 바꾸면 `functions/eval_prompts.py`로 다시 측정(작업 30) |
| `data/departments.json` | 가상 대표메일·공식안내URL | 부서 실제 메일·URL. 부서 배정 규칙은 원본 시트 「부서리스트」 |
| `data/` 데이터 | 가상 데이터 | 동의받은 귀국보고서·현장실습지원센터 후기 연동(동의 조건 동일). `tools/` 변환 → `build_notes.py` 재생성 |
| `data/usage-log.json` | 시드 | 실제 질문 로그(학번 제거)로 대체 |
| CORS `ALLOW_ORIGIN` | Pages + localhost | 학교 화면 주소 |
| 리포트 메일 | 미리보기만(발송 비활성) | NCP Cloud Outbound Mailer 등(작업 43, P2) |
| 보관기간 삭제 | 규칙만 | 스케줄러(Cloud Functions 트리거) |
