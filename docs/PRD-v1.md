### 4-2. 노트 채우기 전략 [v1.2] — "보고서로 만들고, 인터뷰로 갱신하고, 질문이 인터뷰를 이끈다"

FDE 피드백 ①-3("노트가 채워져야 서비스가 도는데 채우는 방법이 비어 있음")과 Q&A의 핵심 지적에 대한 답. 원 설계(보고서 원본 → 노트 생성 → 인터뷰로 갱신)는 유지하고, 빠져 있던 세 가지(생성 규칙·질문함→인터뷰 연결·보고서 틀 밖 질문의 자리)를 채운다.

| 단계 | 규칙 | 담당·작업 |
|---|---|---|
| ① 보고서 → 근거 문단 | 귀국보고서 12문항 → 5칸(지원·학점·비용·생활·팁)은 **고정 규칙**(spec 9장). 현장실습후기는 **문장 단위**로 쪼개(문단 하나에 업무·배운점이 섞임) 문장별로 AI가 칸 1개 선택(T=0, Max 30, frames 밖 응답 폐기) → 노트에 「자동 분류」 라벨 | 원우 16·50 / 미리 50 |
| ② 근거 → 해봤노트 **사전 생성** | `tools/build_notes.py` → `data/notes.json`(보고서 있는 프로그램 71개 + 후기 있는 현장실습). 칸 문장 = 근거 문단 **원문 인용 1:1**(AI 변환 없음 → 환각 0·비용 0). 커버: `forWhom` 템플릿("{국가}권 {분야}를 생각하는 1~2학년"), `evidenceCount`·`lastSemester` 코드 계산, `oneLine`은 근거 많은 칸 첫 문장(칸 상단 AI 한 줄 요약은 P1-여건). `official`은 학점·장학·선발·자격 키워드 정규식. 시연 중 AI 호출 없음 | 원우 26 |
| ③ 인터뷰 → 노트 **갱신** | 공개 동의 통과 문장은 `runtime/noteLines.json`에 쌓이고 `getNote`·`listNotes`·askBoo 근거 풀이 notes.json과 합쳐 쓴다. 같은 칸에 `docType: 인터뷰`로 들어감(배운점·후배 질문은 인터뷰 전용) | 미리 26·74 |
| ④ **질문함 → 인터뷰** | `interviewNext`는 같은 프로그램의 `hold` 질문(최근순 최대 3개)을 **먼저** 묻는다: 「후배가 이렇게 물었어요 — "…" 경험이 있으면 들려주세요」. 응답에 `questionId`, `section: "후배 질문"`. 「경험이 없어요」면 건너뛰고 hold 유지. 그 뒤 근거 적은 칸 순(기존). 기획서 "질문함 → 선배 인터뷰 질문 주제" 약속 | 미리 74 |
| ⑤ **「후배 질문」 7번째 칸** | 네 틀 모두에 추가(`인터뷰로만`). 5칸에 안 맞는 질문("학기 중 인턴 병행?" "비자 연장?")의 자리. 노트에서는 **Q·A 쌍 원문 인용**(배운점과 같은 규칙, 합치지 않음). 같은 질문에 선배 여럿이 답하면 A가 쌓인다. A 문장은 다음 후배의 askBoo 근거가 된다 | 원우 70(frames) / 민지 75 |
| ⑥ 답변 알림 | `saveConsent`가 `answersQuestionId`가 붙은 문장을 통과시키면 그 질문 `status → answered`, 질문자 알림 「내 질문에 선배가 답했어요 · ○○ 해봤노트」. **칸 일치만으로는 알림을 보내지 않는다** | 미리 74 |
| ⑦ 근거 적음 표시 | 근거 1~2건 칸에 「선배 1명의 경험이에요」 라벨. 보류 임계값(3명)은 두지 않는다(2-2) | 민지 75 |
| ⑧ 경험의 시효 | 출처 칩에 **연도**(2024). 2년 넘은 근거만 있으면 칸 아래 「최근 경험이 없어요 · 질문함에 담기」. 운영에서는 신고·콘솔 '검토 필요'로 갱신 | 민지 75 |
| ⑨ 운영 로드맵(슬라이드) | 선배는 보고서를 다시 쓰지 않는다. 귀국보고서 제출·실습 종료 시점에 인터뷰 연결, 항목당 질문 1~2개·5분 안, 현장실습지원센터 후기 연동(동의 조건 동일), 예시답 칩·음성 입력 | 원우 55 |

**인턴 후기와 벡터 RAG**: 연동 전제 시 귀국보고서와 같은 파이프라인 + ① 분류 단계. 벡터 DB는 세우지 않는다(2-2). 업체명 없는 질문은 **직군·기관유형 사전 매칭**(`data/intern-keywords.json`, 원우) → askBoo 1단계 대조 실패 시 후보 업체 1~3개(미리, 작업 81). 그래도 못 잡으면 경량 임베딩(P1-여건, 58③).

## 5. 관리자 콘솔 (PC) — 신규

### 5-1. 원칙

- 경로 `screens/admin/index.html`. **PC 우선**(콘텐츠 폭 1,120px, 최소 1,024px). 모바일 폭에서는 KPI 카드 4개와 부서 드롭다운만 보이고 나머지는 "PC에서 보세요" 안내.
- 디자인 MD 그대로: NAVY 제목·CTA, 흰 카드, 닫힌 팔레트, **증감 배지 중립색**(미답변 질문 감소만 긍정색), BOO 사용 안 함, Lucide 아이콘, 라이브러리 없이 CSS 막대 + 인라인 SVG(오프라인 시연 안전).
- 상단 고정: 부서 드롭다운(「전체」 + 부서 목록) · 기간 선택(학기 ▾ / 월 ▾) · 오른쪽에 「마지막 집계 시각」.
- 탭 3개(같은 화면 안 전환): **수요 현황 / 개선 제안 / 리포트 발행**.
- 모든 수치는 서버 집계. AI는 (a) 개선 제안 문장 (b) 리포트 요약 한 단락, 두 곳에만.

### 5-2. 탭1 수요 현황

**지표 카드 4개(기획서 지표 그대로)** — 수치 28px + 증감 배지 「▲ 12% 전월 대비」(기간이 학기면 '전 학기 대비')

| 지표 | 산식 | 색 |
|---|---|---|
| 질문 수 | 기간 내 물어보기 질문 건수(사용 로그 + 시연 중 실제 질문). 부서 필터 = 질문의 프로그램 → `programs.json`의 운영부서. 프로그램이 안 잡힌 질문은 「전체」에만 포함, '분류 안 됨' 행으로 표시 | 중립 |
| 미답변 질문 | `status = hold` 건수. 보조 문구 「보류율 n%」 | 감소 시 긍정, 증가 시 중립 |
| 신규 수요 | 보류 질문을 프로그램(없으면 키워드)·칸으로 묶어 **3건 이상인 묶음 수** 중 해당 프로그램 노트가 없거나 그 칸이 비어 있는 묶음 | 중립 |
| 개선 요청 | 탭2 제안 중 상태 「새로 옴」 건수 | 중립 |

**표·그래프(위에서 아래로)**
1. 프로그램별 질문 순위 Top 10 — CSS 막대(NAVY 단색, 값 라벨), 행 클릭 → 그 프로그램의 질문 칸 분포(지원·학점·비용·생활·팁·배운점)가 오른쪽에 펼쳐짐
2. 칸별 질문 비율 — 가로 막대 5개(분야 색 아님, NAVY 농도 아님: 단색 + 라벨)
3. 단과대·학과별 질문 분포 — 표(학과, 질문 수, 보류율). 상위 8개 + '그 외'
4. 노트 현황 — 노트 수 / 근거 문단 수 / 인터뷰 수 / 공개 동의율 (작은 수치 4개 한 줄)
5. (P2) 주차별 추이 — 인라인 SVG 선 그래프(질문·보류 두 선)

### 5-3. 탭2 개선 제안

- 카드 목록. 카드 = 유형 라벨(**신규 수요**=정보 / **안내 보강**=주의 / **검토 필요**=주의) + 제목(18px) + 제안 문장(AI, ✦ HUFS GREEN 아이콘) + 「근거 질문 N건 · 최근 2026-11」 + 「펼치기」→ 질문 원문 목록(날짜·학과·칸, 학번 없음) + 상태 선택(새로 옴 / 검토 중 / 반영됨 / 보류) + 담당 부서.
- 정렬: 새로 옴 → 근거 질문 많은 순. 부서 드롭다운으로 필터.
- **신고된 진술** 섹션(카드 목록 아래): 신고된 문장, 근거 원문, 신고 사유, 노트명, 상태(숨김 중 / 공식 안내 연결됨 / 복구). 작업 33의 "부서 리포트 표시"는 여기로 흡수.
- 생성 규칙(서버·사전 생성): 보류 질문 + 규정성 질문 + 같은 프로그램·칸에 3건 이상 반복 질문을 묶음 → 묶음마다 AI 1회 → `{"유형":"안내 보강|신규 수요|검토 필요","제목":"…","제안":"…"}`(T=0, Max 150) → **사후 검증**: 제안문에 묶음 질문에 없는 숫자·고유명사가 있으면 폐기하고 제목만 둠. 시드 로그에 대한 제안은 `data/suggestions.json`으로 **미리 만들어 둔다**(시연 중 AI 호출 없음). 시연 중 새로 생긴 보류 질문은 「새 질문 N건 — 다음 집계 때 제안 생성」 표시만.

### 5-4. 탭3 리포트 발행

| 구역 | 내용 |
|---|---|
| 발행 설정(부서별 저장) | 주기 **월간 / 학기당** · 발행일(월간: 매월 n일 / 학기당: 학기 종료 후 n일) · 받는 사람(부서 대표메일(가상) + 추가 이메일 입력, 이메일 형식 검사) · 포함 항목 체크(지표 4개 / 프로그램 순위 / 미답변 질문 목록 / 개선 제안 / 신고 진술) · 「저장」(Primary) · 저장 완료 토스트 |

AI 요약 한 단락: 입력 = 지표 4개 수치 + 상위 프로그램 3개 + 제안 제목 3개 → `{"요약":"…"}`(T=0, Max 200) → 사후 검증: 요약 속 숫자는 입력에 있는 숫자만 허용. 실패 시 템플릿 문장으로 대체.

### 5-5. 완료 기준

- 부서를 바꾸면 모든 수치·표·제안이 1초 안에 바뀌고, 카드 수 = 목록 수(디자인 MD 9절 수치 일치).

- PC 1,280px·1,024px·모바일 390px에서 깨지지 않음.
