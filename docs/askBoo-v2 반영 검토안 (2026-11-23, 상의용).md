**결론.** "AI가 보고서를 이해 못 한다"는 A 하나다. 심사위원이 보는 건 A와 B다. 고르기 구조를 버리는 게 아니라 **고르기 위에 "답 쓰기"를 얹고, 앞에 "질문 정리"를 둔다.** 가드레일(프로그램 범위 안에서만 근거 꺼내기·사후 검증·동의 문장만 공개·보류→질문함→인터뷰)은 그대로다.

**같은 날 봉인 1차(#150, 11/23 15:12)가 보여 준 것.** 근거 없는 답 0건·함정 10/10은 통과했지만 정답률 23/30이고, **틀린 7개는 HCX·Sonnet이 똑같이 틀렸으며 모두 AI를 부르기 전 코드 단계의 보류**였다(규정 질문 못 알아봄 3 · 보고서 칸에 없는 주제 3 · 프로그램 못 찾음 1). 즉 지금 병목은 모델이 아니라 **정규식 문지기**다. 원우 #151이 봉인을 보지 않고 새 확인용 질문으로 잰 결과도 같다(규정 판별 2/12 → 11/12, 주제어 12/20 → 14/20, "낱말 목록으로는 안전하게 조금만 나아진다"). 그래서 v2를 기다리지 않고 오늘 v1 안에서 두 가지를 먼저 고친다(2-6).

### 2-2. 응답 모양 변경 (spec 4장 askBoo)

- payload: `{question, history?: [{question, status, program?}]}` — 화면이 최근 4턴을 보낸다(sessionStorage, 3-6). 서버는 기억하지 않는다(interviewNext와 같은 원칙).
- `status: "ok"`: `lines[].cites: ["R213-6", …]` 추가(문장이 인용한 sourceId). `sources`는 그대로. `fallback: true`면 지금처럼 원문 인용 줄.
- **새 상태 `status: "chat"`**: `{message, chips:[{label, action: "notes"|"save"|"ask", payload}]}`. 질문함에 저장하지 않는다.
- `status: "notes"`: 카드에 `oneLine`(노트 커버 한 줄, 요약 문단이 생기면 그것) 추가. 현장실습 유형 안내일 때 `kinds:[…]`.
- `status: "hold"`: 그대로. 단 ①에서 `의도: 대화`로 판정된 말은 hold가 아니라 chat이므로 질문함에 들어가지 않는다.

### 2-3. 화면 변경 (talk.js 물어보기, 민지)

- `renderAnswer`에 `notes`·`chat` 상태 추가(5번 버그 수정 포함). notes는 노트 카드(7-③ 커버 축소형) 목록, chat은 BOO 말풍선 + 칩.
- ok 답: 문단 아래 근거 블록은 그대로, 문장 끝에 작은 인용 번호 「¹ ²」(HUFS GREEN 12px), 「근거 원문 보기」를 펼치면 인용한 문장이 번호 순으로 보인다. 폴백 줄 「근거 원문」 라벨은 그대로.
- 대화 맥락: 물어보기 대화를 sessionStorage에 저장하고(3-6과 같은 저장소) askBoo에 최근 4턴을 보낸다.

### 2-5. 측정·비용

- 개발용 70개 전부 재실행(원칙 v2 8절) + **다중 턴·탐색·대화 20개 추가 → 90개**. 기대답은 원우가 확정. 새 20개 유형: 「말고」 제외, 「그럼 ○○는요?」 이어 묻기, 「어디 있어요·추천」 탐색, 「아까 한 얘기」 대화, 현장실습 나라 질문.

### 3-5. 해봤노트 「후배 질문」 칸 정리 (결정 ③)

- **이유**: 후배 질문은 질문함에 쌓였다가 다음 선배에게 나가면 되고, 누적 질문을 노트에 보일 이유가 없다(미리 11/23). 답 문장은 남겨야 한다(다음 후배의 근거, 완성 기준 S8).

Q·A 쌍은 **질문자만** 내 보관함 질문 상세에서 본다(이미 구현됨). 해봤노트에서는 그 문장에 중립 라벨 「후배 질문에 답한 문장」. `answersQuestionId`·알림·`answered` 전환은 그대로.

| 규정 판별 정규식(`OFFICIAL_RE` → 2-6 ①′ 넓힌 표현 + 말투 예외) | 반만 버팀 | 규정 질문은 운영에서도 반드시 공식 안내로 보내야 하므로 정규식은 **보수 규칙**으로 남긴다(걸리면 무조건 official). 못 잡는 표현은 질문 정리(①)의 `의도: 규정`이 보완한다. 넓힌 표현도 결국 낱말 목록이라 운영 중 들어온 규정 질문으로 확인용 세트를 계속 늘린다(#151 "한 번만 잰다" 원칙) |
| 귀국보고서 12문항 → 5칸 고정 매핑 | 반만 버팀 | 양식이 바뀌면 깨짐. 현장실습 후기의 "AI가 칸 하나 고르기"가 일반 경로 |
| 가상 보고서 전부 동의 간주 | **운영에선 0건** | 기획서가 미동의 보고서 소급 활용을 금지. **보고서·후기 제출 양식에 공개 동의 체크 + 5분 인터뷰 연결**(PRD 4-2 ⑨)을 붙이지 않으면 출시 시점 근거가 0이다. 도입기 첫 학기 = 동의 수집기 |
| 근거 1~2건 칸 | 운영 첫 해의 기본 상태 | 「선배 1명의 경험이에요」 + 그 아래 「이 경험을 한 선배에게 더 묻기 · 질문함에 담기」. 답변 품질보다 수집 장치(3-4)가 중요 |
| 프롬프트 회귀 세트·검토 큐 | 필요 | 90개 세트를 실제 질문으로 계속 늘리고, 콘솔 「검토 필요」 큐(신고·보류율 높은 프로그램). 사람 1명 주 1시간 |
| 비용 | 문제 아님 | 월 5천 질문 기준 수만 원대. 운영노트 4장 실측 |

발표 로드맵 슬라이드(PRD 11장)에 "정규식 사전 → 질문 정리 + 임베딩", "제출 시 동의 수집"을 **이번에 뺀 것의 행선지**로 적는다. 심사위원이 "실현 가능하냐"고 물을 때의 답이다.
