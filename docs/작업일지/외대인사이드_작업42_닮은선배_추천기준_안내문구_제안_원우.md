# 작업 42 · 닮은선배 「추천 기준」 안내 문구 제안 (원우 → 민지, 11/25)

> 계기: 재학생 A(83, 11/25) 「닮은 선배의 기준이 무엇인지 미리 알 수 있으면 좋겠다」.
> 범위: **문구만** 제안한다. 점수 규칙(`functions/score.py`, 원우)과 서버는 바꾸지 않는다. 화면(`screens/senior/`)과 디자인 규칙(`docs/design-rules.md` 7-④)은 민지 파일이라 민지가 정한다.
> 시기: 민지 닮은선배 화면 작업(기준 노트, ~11/30)과 겹치므로 그때 같이 넣거나 12/3 코드 프리즈 전에. 측정(88·봉인)과는 관계없음(askBoo 아님).

## 1. 지금 규칙 (코드 그대로 — `functions/score.py`, spec 4장 recommendSeniors)
- **후보**: 그 노트(내가 보는 프로그램)를 경험한 선배 전부. 본인·직원은 뺀다.
- **순서(점수)**: 같은 학과 5 · 같은 이중전공 4 · 같은 단과대 3 · 함께 들은 비교과 2(여러 개여도 한 번). 점수가 같으면 수락 대기 요청이 적은 선배 → 최근 학기에 다녀온 선배.
- **이유 문장**: AI가 아니라 코드 템플릿 — 「희망 프로그램을 경험했어요」 + 「같은 ○○대학」·「같은 ○○과」·「이중전공 ○○ 같음」·「○○ 함께 이수」.
- 화면에는 이미 카드마다 일치 칩(관심 경험·전공·단과대·비교과)과 이유 1줄이 있다(디자인 규칙 7-④). 학생 A는 **목록을 보기 전에** 기준을 알고 싶어 했다.

## 2. 제안 — 둘 중 하나

**A(추천). 상단 설명을 두 줄로** (7-④ 「상단: 제목 + 설명」 자리, 새 요소 없음)
> 내가 궁금한 경험을 해본 선배 중, 출발점이 비슷한 선배를 추천해요.
> **학과 → 이중전공 → 단과대 → 함께 들은 비교과 순으로 겹칠수록 앞에 보여 줘요.**

- 장점: 화면 요소를 늘리지 않음, 처음 들어오면 바로 보임. 단점: 한 줄이 길다(390px에서 두 줄로 꺾일 수 있음 — 민지 판단)

**B. 「추천 기준」 펼치기** (설명 옆 텍스트 버튼, 누르면 3줄)
> - 내가 보고 있는 해봤노트의 경험을 해본 선배만 추천해요.
> - 학과가 같으면 가장 앞, 그다음 이중전공·단과대·함께 들은 비교과 순이에요.
> - 이름·학번은 서로 보이지 않아요.

- 장점: 자세함. 단점: 요소 하나 추가(터치 44px·접근성 확인 필요)

## 3. 쓰지 않을 말
- 「AI가 골라요」 — 추천은 AI가 아니라 규칙이다(방어 자료 변경 「추천 이유 AI → 템플릿」과 같게).
- 점수·가중치 숫자(5·4·3·2), 매칭률 % — 7-④ 「매칭률 %는 산식이 확정된 경우에만」, 숫자를 보이면 줄 세우기처럼 읽힘.
- 「성적」·「입학년도」 — 쓰지 않는 정보다(입학년도는 학기 계산에만, 화면에 안 보임).

## 4. 확인한 것(11/25)
