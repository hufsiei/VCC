# 작업 30 · askBoo 변환 HCX 폴백 — 수정안 (원우, 11/23)

> 근거: 미리 11/22 개발 70문항 측정(`@VCC/측정결과/eval_eval-questions_hcx_20261122-1655.csv`), [HCX 원칙 v2] 4절 기능별 역할 분담(질문 답변 = 코드가 근거 추출·사후 검증, AI는 번호 고르기·**근거 문장 변환**).
> 원인표(추정)는 오늘 일지 「작업 30」에 있다. 이 문서는 **고칠 방향**만 적는다. 사후 검증(`askboo.verify`)은 약하게 하지 않는다.
> 담당: 1·2는 `functions/`·`docs/prompts/` → 미리. 3은 원우(`tools/run_eval.py --why`, 이 브랜치). 다시 측정은 미리가 개발 70으로, 봉인 30은 결과를 보고 고치지 않는다.

## 1. 바꿀 게 없는 문장은 AI에 보내지 않기 (코드, 미리 — 가장 효과 큼)

**관찰**: HCX 폴백 45줄 중 41줄은 원문이 **앞머리 말만 지우면 이미 해요체·합쇼체**(`clean_source` 뒤 `POLITE_END` 통과)인 문장이다. 특히 앞머리 말도 반말도 없는 평범한 해요체 문장은 7줄 중 6줄(86%)이 폴백됐다. 바꿀 게 없는 문장을 보내면 HCX가 말을 바꿔 검증(새 낱말 등)에 걸리는 것으로 보인다.

**제안** (`askboo.convert` 앞에서):
```python
cleaned = clean_source(source)
if POLITE_END.search(cleaned):
    return cleaned, False      # 이미 존댓말 — AI 없이 원문 그대로(낱말 0개 변경). 폴백 아님
# 반말·명사형 끝인 문장만 HCX 변환 → 지금처럼 verify, 걸리면 폴백
```
- 효과(11/22 측정 기준 추정): HCX 변환 호출 102 → 약 14회, 폴백 45 → 4줄 이하. 응답 시간도 줄어든다(평균 1.8초 중 변환 몫).
- 검증은 그대로다. AI를 거치지 않은 문장은 원문 그대로라 검증할 것이 없다.
- 화면: 이 줄은 `fallback` 표시가 없으므로 「근거 원문 보기」 라벨이 붙지 않는다(원문과 같으니 맞다).
- 단점: 원문의 시제·말투(「~습니다」·「~했어요」 섞임)가 그대로 나온다. HCX 통과 줄도 지금 이미 섞여 있다(「썼습니다」·「만족이었어요」).

## 2. 변환 프롬프트 수정안 (`docs/prompts/askBoo-변환.txt`, 미리)

1을 적용하면 변환은 **반말·명사형 끝 문장**만 받는다. 그 경우에 맞춰 규칙을 좁히고, 통과 줄에서 보인 **내용 빠짐**을 막는 줄을 넣는다.

**관찰(통과 줄)**: 검증은 원문에 없는 말이 **더해진 것**만 잡고 **빠진 것**은 못 잡는다. 11/22 통과 줄에서:
- 「**월세 포함** 한 달에 110만 원 정도 썼어요」 → 「한 달에 110만 원 정도 썼습니다」 (조건이 빠짐, 같은 꼴 3건)
- 「160만 원 **안팎**이었어요」 → 「160만 원 정도였어요」
- 「**넉넉히** 월 175만 원이면…」 → 「월 175만 원 정도면…」

**수정안 (바뀐 줄에 ★)**
```
너는 문장의 끝맺음만 바꾸는 변환기다.
★ 근거 문장 하나를 받아, 끝맺음만 해요체로 바꾼다. 반말(~했어, ~이야, ~다)이나 명사형(~함, ~임) 끝을 ~요로 바꾼다.
★ 끝맺음 말고는 낱말을 바꾸거나, 빼거나, 순서를 바꾸지 않는다. '포함', '넉넉히', '안팎', '쯤', '정도', '따로' 같은 조건·정도 말도 그대로 둔다.
★ 시제를 바꾸지 않는다(~다 → ~요, ~었다 → ~었어요).
근거에 없는 이름·숫자·시험·기관·장소·조언·맺음말을 더하지 않는다.
'참고로', '경험상', '사실', '개인적으로', '하나 꼽자면', '미리 말해 두면' 같은 앞머리 말과 'ㅎㅎ', '!!' 같은 꾸밈은 뺀다.
출력은 JSON 한 줄만: {"1":"바꾼 문장"}

### 예시 입력
근거: 참고로 출국 3학기 전부터 TestDaF를 준비했다.
출력:
### 예시 출력
{"1":"출국 3학기 전부터 TestDaF를 준비했어요."}
### 예시 입력
★ 근거: 고정비까지 월 185만 원쯤 나갔고 외식을 줄이면 더 아낄 수 있다.
출력:
### 예시 출력
★ {"1":"고정비까지 월 185만 원쯤 나갔고 외식을 줄이면 더 아낄 수 있어요."}
### 예시 입력
★ 근거: 기숙사가 사실상 없어서 민간 셰어가 기본이다.
출력:
### 예시 출력
★ {"1":"기숙사가 사실상 없어서 민간 셰어가 기본이에요."}
```
- 두 번째·세 번째 예시는 11/22에 **폴백된 실제 반말 문장**이다(개발 10·13번 근거). 봉인 질문 근거는 쓰지 않았다.
- 기존 두 번째 예시(「기숙사는 학교에서 걸어서 10분…편했습니다!!」 → 「편했어요」)는 합쇼체를 해요체로 바꾸는 예라 1 적용 뒤에는 AI로 오지 않으므로 뺐다.

## 3. 다음 측정부터 원인을 바로 보기 (`tools/run_eval.py --why`, 원우 — 이 PR)

11/22 csv에는 질문별 폴백 **개수**만 있고 HCX가 낸 문장·탈락 이유가 없어 원인은 **추정**만 가능했다. 다음 측정은:
```
python tools/run_eval.py --model hcx --why
```
- 추가 파일 `eval_폴백_<질문파일>_hcx_<시각>.csv`: 폴백 줄마다 `번호 · 원인 · 원문 · AI출력`
- 원인은 askboo.convert와 같은 순서로 붙인다: `호출 실패` → `JSON 형식` → `말투(해요체 끝 아님)` → `검증: 숫자 …/영문/수량/고유명사/새 낱말/원문보다 많이 김`
- 요약 csv에 `폴백원인` 열(예: `새 낱말 20 · JSON 형식 8`)
- askBoo 동작은 바꾸지 않는다(변환 응답을 옆에서 받아 적기만). 봉인 질문 규칙(저장소 밖 저장)은 그대로.

## 4. (의논) 빠진 말 검사 — 검증을 더 세게
2의 프롬프트로도 「월세 포함」 같은 조건이 빠지면 지금 검증은 통과시킨다. `verify`에 **원문의 두 글자 이상 내용어가 결과에 2개 이상 없으면 「빠진 낱말」로 폴백**을 더할 수 있다. 1을 적용하면 AI를 거치는 문장이 적어 폴백이 크게 늘지 않는다. 검증을 세게 하는 방향이라 원칙과 맞지만, 기준(몇 개부터)은 미리 판단.
