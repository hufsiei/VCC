## 1. 한 줄 결론 [v2 수정]

코드가 할 수 있는 일은 코드가 하고, AI에게는 정답이 있는 작은 일만 JSON으로 시킨다.
모델은 호출별 PROVIDER 스위치(hcx | claude)로 관리한다 — askBoo(고르기·변환)는 검증된 HCX 유지, 미검증·자유생성 호출은 기준 미달 시 그 호출만 Claude로 교체한다. CLOVA Studio는 최소 1개 이상 기능에 반드시 유지한다(기획서 기재, 네이버클라우드상 자격, 네이버 심사위원).

## 2. 관찰된 문제

- HCX-005(Temperature 1)에 근거 문단을 시스템 지침·입력창 어디에 넣어도, 근거에 없는 내용을 지어냄. 예: "HUFS 특강" 질문에 없는 내용, 독일 교환 질문에 근거에 없는 "TestDaF 4점", "Goethe" 등 시험명·조언·맺음말 추가.
- 프롬프트에 "근거에 없는 내용은 말하지 마" 같은 지시를 강화해도 해결되지 않음.
- HCX-007: JSON을 출력한 뒤에도 뒤에 답변·설명을 계속 붙임(Max tokens 20480, 중단 문자 없음 상태).
- 자유 문장 변환을 시키면 형식을 무시하고 "~를 추천합니다. ... [1]" 식의 일반 조언문을 생성.
- 이전 대화 기록이 남아 있으면 결과가 오염됨 → 테스트마다 대화 초기화.
- [v2 추가] HCX-007 고르기 재시험(11/16, 근거 3줄)에서도 JSON 뒤 자유 생성이 붙음을 재확인. 단, 파싱 후 번호 선택 자체는 정답이었음. → **모델 평가는 화면에 보이는 원시 출력이 아니라 "첫 JSON 파싱 후 결과" 기준으로 한다.** 고르기 선택 품질은 감이 아니라 정답셋 측정으로 판정한다(8절).

## 3. 효과가 있었던 구조 (askBoo 4단계 + [v2] 5단계)

1. 코드: 프로그램명 대조. 질문 속 프로그램명을 프로그램 목록과 글자 그대로 대조. 근거 0건이면 AI를 부르지 않고 status "hold" → 질문함 등록 → 닮은 선배 연결.
2. 코드: 근거 추출. 그 프로그램의 근거 문단만 번호를 붙여 꺼냄.
3. AI: 번호 고르기. Thinking 끔, Temperature 0, Top P 0.1, Max tokens 30. 출력 `{"관련":[1,3]}`. 코드가 첫 번째 `{...}`만 파싱하고 없는 번호는 버림.
4. AI: 근거별 한 문장 변환. 고른 근거만 넣음. Temperature 0, Max tokens 150. 출력 `{"번호":"해요체 한 문장"}`. 코드가 문장을 조립하고 출처 칩(문서유형·프로그램·학기)을 붙임.
5. [v2 추가] **코드: 사후 검증.** 변환·요약 문장에 근거 문단에 없는 고유명사·숫자가 등장하면 그 문장을 기계적으로 탈락시키고 "근거 원문 보기" 폴백으로 대체한다. (2절의 "TestDaF 4점", "Goethe" 같은 사례를 모델과 무관하게 잡는 최종 안전망. 정규식 + 근거 문단 대조로 구현, AI 불필요)

검증 결과(11/14): `{"1": "출국 3학기 전부터 TestDaF를 준비했어."}` — 근거 밖 내용 없음. 말투만 남은 과제(완성 예시 문장을 프롬프트에 넣거나, 코드가 메타데이터로 "○○ 선배는" 같은 앞머리를 붙이는 방식으로 해결).

## 4. 기능별 역할 분담 [v2 수정: 모델 열·전환 기준 추가]

| 기능 | 코드가 하는 일 | AI가 하는 일 | 모델(초기) | 전환 기준 |
|---|---|---|---|---|
| 질문 답변 (askBoo) | 프로그램명 대조, 근거 추출, 0건이면 보류, 사후 검증(5단계) | 관련 번호 고르기, 근거 문장 변환 (JSON) | HCX | 정답셋 고르기 정확도 90% 미만이면 Claude |
| 닮은 선배 | 점수 계산 전부 (common/score.js) | 없음 | — | — |
| 인터뷰 (인터BOO) | 노트 틀 칸별 기본 질문 목록·순서 관리(교환·파견 6칸, 배운점은 마지막에 묻기 — PRD 4-1) | 답변이 항목을 채웠는지 판정 `{"충분":true}`, 짧은 꼬리 질문 1개 | HCX (11/19까지 검증) | 판정 오류 발견 시 Claude |
| 노트 정리(요약) | 항목별 칸 채우기, 사후 검증(5단계) | 답변 한 문장 요약 | **Claude 권장** | 사실을 담는 자유 생성이라 HCX 약점에 정면으로 걸림 |
| 원문 일치 검사 | 사후 검증(5단계)을 먼저 통과시킴 | `{"일치":true/false}` | **Claude 권장** | 생성 모델과 검증 모델을 분리해 순환 검증을 끊는다 |
| 본인 식별 문장 표시 (공개 동의) | 성적 숫자·수상·실명·특정 인물 정규식·사전으로 찾아 기본 비공개 | 없음 | — | — |
| 배운점 (해봤노트 표시) | 선배별 원문 문장을 그대로 인용, 합치지 않음 | 없음 | — | 주관적 회고를 합치면 일반화가 생김 |
| 자소서용 요약 (P1) | 칸별 문장 선택·조립 | 문장 하나씩 1인칭 변환 JSON | HCX | 입력에 없는 경험·수치가 나오면 Claude |
| 쪽지 검사 | 금지어 목록, 연락처·학번 정규식 | 개인정보·비방 판정 `{"ok":false,"reason":"…"}` | HCX (정답셋 측정 후) | 정확도 미달 시 Claude |
| 문단 분류(인턴 후기) | frames.json 칸 목록 제공, 목록 밖 응답 폐기 | `{"칸":"업무내용"}` | HCX (원우 정답 칸으로 측정) | 정확도 미달 시 Claude |

[v2] 핵심 원칙: **사실을 '만드는' 호출(변환·요약)과 사실을 '지키는' 호출(일치 검사)을 같은 계열 모델에 맡기지 않는다.** 환각 방지 체계의 최종 관문을 가장 못 미더운 모델에 세우지 않는다.

## 5. 설정·프롬프트 규칙

- 사실을 다루는 호출은 모두 Temperature 0, Thinking 끔, Max tokens를 출력 크기에 딱 맞게(번호 고르기 30, 문장 변환 150).
- 출력은 항상 JSON. 코드는 첫 번째 `{...}`만 파싱하고 나머지는 버린다. 형식이 틀리면 AI 답을 버리고 기본 문구(예: "근거 원문 보기")를 보여 준다.
- 한 번에 한 가지 일만 시킨다. "고르고 + 요약하고 + 조언"을 한 호출에 넣지 않는다.
- AI에는 고른 근거만 넣는다. 전체 근거를 넣으면 섞어서 지어낸다.
- 테스트할 때는 매번 대화 초기화.
- 규정성 진술(학점 인정·장학금·자격 요건·선발 기준)은 "개인 경험" 표시 + 공식 안내 링크.
- [v2 추가] 서버 함수의 AI 호출은 `callAI(작업명, 입력)` 한 관문으로 모으고, 작업명→모델 매핑은 설정 한 곳(PROVIDER 표)에서만 바꾼다. API 키는 모델 종류별로 모두 서버 함수에만 둔다(브라우저 노출 금지 동일).
- [v2 추가] 변환·요약 출력은 3절 5단계(사후 검증)를 반드시 거친다.

- [v2 폐기] ~~"모델 교체(해외 AI)는 하지 않는다"~~ → **호출별 PROVIDER 스위치 + 4절 전환 기준으로 대체.** 폐기 근거:

  - 개인정보 질문 방어: 시연은 가상 데이터 전용이고, 실운영에서도 원문을 AI에 넣지 않는 설계가 본질적 방어다. 질의 대응 문구 — "모델은 어댑터 구조라 교체 가능하며, 실제 도입 시 대학의 데이터 거버넌스 요건에 맞는 모델로 전환할 수 있다." (정책화 답변으로도 사용)
  - 점수 구조: NCP 가점은 5점 이내, 시연 중 환각 1건은 구현 완성도 30점과 "근거 없는 답변 0건" 주장을 무너뜨린다.
- [v2 추가] 전환하더라도 CLOVA는 최소 1개 기능(쪽지 검사·문단 분류·임베딩 키워드 중 측정 통과 항목)에 유지 — 네이버클라우드상 자격과 "CLOVA 활용" 사실 유지.
